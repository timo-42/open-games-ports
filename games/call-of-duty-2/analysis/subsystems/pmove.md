## 2. Architecture as implemented in this binary

[obs] Everything is a single, server-only build of the shared "bg" code: no prediction, no client-side callers. There is one pmove entry (`PM_Pmove` 0x080e9464) with two callers in the game module:

1. `ClientThink_real` 0x080f5d2e (chunk 046, line ~161): for a connected client with `sessionState` playing, builds a zeroed 0xf8-byte `pmove_s` (`memset(&pm,0,0xf8)`), copies `ps`, `cmd` (the incoming usercmd) and `oldcmd` (`client->oldcmd`), sets `tracemask = 0x2810011` if `pm_type < 6` else `0x810011`, `clipType (pm+0xe4) = 1`, then runs the view-effect helpers and calls `PM_Pmove`. After it: if `pm.spawnEvent != 0` calls `G_SpawnPmoveEventEntity(pm.eventOrigin, pm.eventTime, &pm)`; sets `ent->field_e0` from `ps.pm_flags & 2`; copies `ps->origin`/`mins`/`maxs` to the entity; emits `BG_PlayerStateToEntityState(&ps, ent, 1, 1)` (or `G_PlayerStateToEntityState` when dvar at `g_087a248c` is set); then `Client_DispatchEvents`.
2. `Client_ProcessButtonsAndDrop` 0x080f4eb2 (chunk 045, provisional) for `sessionState == 2` (spectator): zeroed pmove, `tracemask = 0x800811`, `clipType = 1`, `PM_Pmove`, then `SV_UnlinkEntity`.

[obs] `ClientThink_real` clamps the command time first: `serverTime <= level.time + 200` and `>= level.time - 1000`; skips if `msec = serverTime - ps.commandTime` is not positive unless the entity number differs; `msec` capped at 200. `pm_flags 0x8000` is set/cleared from `client->field_27b4` before the move (frozen controls).

### 2.1 PM_Pmove / PM_SingleStep

[obs] `PM_Pmove` 0x080e9464: if `ps->commandTime <= cmd.serverTime`: if `commandTime + 1000 < serverTime`, `commandTime = serverTime - 1000`; `pm->numtouch (pm+0x40) = 0`; loop: `step = min(final - commandTime, 0x42 (=66 ms))`, `pm->cmd.serverTime = commandTime + step`, `PM_SingleStep(pm)`, `pm->oldcmd = pm->cmd`. (So `oldcmd.serverTime` is the intermediate sub-step time.)

[obs] `PM_SingleStep` 0x080e8934 (decomp checked). In order:
1. `BG_UpdateConditionsFromPmove(pm)` 0x080d9a1c (animscript conditions).
2. `pm_flags & 0x8000` => buttons masked `& 0x2300`, forward/right = 0, velocity = 0. `cmd.buttons & 0x40000` => buttons `& 0x43300`, move = 0. `pm_flags &= ~0x10000`. `pm_type > 5` => `tracemask &= ~0x2000000`.
3. Prone/ADS flag housekeeping (`pm_flags` bits 0x1, 0x800, 0x40), `stance = PM_StanceIndex(ps)`; prone with `pm_flags & 0x40` zeroes move.
4. `eFlags`: bit 0x200000 from `cmd.buttons & 0x40000`; bit 0x40 (firing) recomputed (needs `pm_type != 5`, `pm_flags & 0x1000 == 0`, `weaponstate` 0 or 3, `PM_Weapon_GetClipAmmo != 0`, button 1). `pm_type < 6` and no `0x4001` buttons clears `pm_flags & 0x1000`.
5. `pml` zeroed (0x7c bytes); `msec = clamp(cmd.serverTime - commandTime, 1, 200)`; `ps->commandTime = cmd.serverTime`; saves `previous_origin/velocity`; `frametime = msec*0.001`.
6. `PM_Weapon_UpdateAttackMeter`, `PM_UpdateViewAngles` (includes `PM_UpdateLean`), `Angles_ToVectors(viewangles, pml.forward/right/up)`, backpedal flag (`pm_flags 0x80` set if forwardmove<0, cleared if forward>0 or pure strafe), `pm_type>5` or (prone && flag 0x800) zero move, `Mantle_ClearSurfaceFlag`.
7. `switch (pm_type)` [obs]:
   - `0` and `default` (includes 6 and unknown >7): if `eFlags & 0x300 == 0` [normal]: when not mantling (`pm_flags & 4 == 0`): `PM_CheckDuck`, `PM_GroundTrace`; then `Mantle_Debug(pm,&pml)` (the real mantle trigger, see 5); if still not mantling: `PM_UpdateWeaponFlag40`, `PM_UpdateFlag100`, `PM_SmoothBodyAngles`, (`pm_type == 6`: `PM_ReduceGroundSpeed`), `PM_CheckLadder`, `PM_DropTimers`, then `PM_LadderMove` 0x080e847e if `pm_flags & 0x20`, else (decomp 0x80e8934 lines 150-157, `local_80 == pml+0x2c`) the function at 0x080e23f8 when `pml.walking == 0` and the function at 0x080e25a6 when `pml.walking != 0`; `PM_GroundTrace`, `PM_Footsteps`, `PM_Weapon_Frame`, `PM_CheckMoveBump`; velocity re-derived from origin delta if the resulting squared speed is below 0.25x of the intended speed; `smoothedVelocity` blend (`min(frametime,1)`); `Sys_SnapVector(velocity)`. If mantling: `PM_Flags_EndLadder`, `groundEntityNum = 0x3ff`, `pml.walking = 0`, weapon flags, `PM_CheckDuck`, `Mantle_UpdateMove(pm, ps, &pml)`, `PM_Weapon_Frame`. If `eFlags & 0x300` (mounted/locked state [inf]): velocity cleared, `PM_CheckDuck`, `PM_DropTimers`, `PM_Footsteps`, `PM_Weapon_ForceReady_Entry`.
   - `1`, `7`: linked pm types: ladder ended, airborne state forced, velocity zeroed, `CheckDuck`, `DropTimers`, `Footsteps`, `Weapon_Frame`. [inf] `PM_NORMAL_LINKED`/`PM_DEAD_LINKED` (player attached to a moving entity).
   - `2`: `PM_FlyMove` (noclip-like, rate 9, no gravity; PM_CmdScale x3). `3`: `PM_ClimbMove` (UFO-like; cmd scale x6). `4`: `PM_CheckDuck`, `PM_FreeMove` (spectator; scale `player_spectateSpeedScale`; extra friction `speed*5*frametime`). `5`: no movement (intermission), only weapon flag/pos-frac.
   - Note on 0x080e23f8 / 0x080e25a6: the chunks name them `PM_WalkMove` / `PM_Move`, but the call condition shows 0x080e25a6 runs when walking (and starts with the jump test `Player_TryJump`, friction, ground clip, step-slide) while 0x080e23f8 runs when airborne. In Q3 terms 0x080e25a6 = walk move and 0x080e23f8 = air move [inf from the call site; both bodies were only read via chunk comments]. See 8.2.

[inf] pm_type numbering (not a symbol; derived from the switch): 0 normal, 1 normal-linked, 2 noclip, 3 ufo, 4 spectator, 5 intermission, 6 dead, 7 dead-linked. `pm_type < 6` is used everywhere as "alive and controllable" (jump, mantle, weapon frame, `tracemask` body bit). chunk_041's header comment (0 normal, 2 spectator, 3 dead, 4 freeze) is wrong.

### 2.2 Movement primitives (chunk 041, 043)

- `PM_ClipVelocity` 0x080e14d4 [obs]: overbounce fixed at 1.001 style: `backoff = dot(in,n); out = in - n*(backoff - 0.001*|backoff|)` computed as `VectorMA(in, -(backoff - 0.001*|backoff|), n)`.
- `PM_Friction` 0x080e156e [obs]: speed `< 1` -> velocity zeroed. Ground drop = `control * friction * frametime` where `control = max(speed, stopspeed)`; `x0.3` when `pm_flags & 0x200` (landing slowdown), `xJumpScale` when `pm_flags & 0x80000`; skipped if `groundTrace.surfaceFlags & 2` (slick) or `pm_flags & 0x400` (knockback). Spectator (pm_type 4) adds `speed*5*frametime`.
- `PM_Accelerate` 0x080e188e [obs]: ordinary branch `accelSpeed = accel*frametime*max(wishspeed, stopspeed)` capped by `wishspeed - dot(velocity,wishdir)`, passed through `PM_ClampAcceleration` 0x080e17fe (dvars `inertiaMax`, `inertiaAngle`, `inertiaDebug`; pm_type 2 exempt; uses `oldVelocity` ps+0x2c). If `pm_flags & 0x20` (ladder) it steers velocity toward `wishdir*wishspeed` instead.
- `PM_CmdScale` 0x080e1c58 [obs]: `speed * max(|fwd|*(back? backSpeedScale), |right|*strafeSpeedScale) / (len*127)`; x0.4 if `pm_flags & 0x100` or `leanf != 0`; pm_type 2 x3, 3 x6, else stance factors (crouch 0.65, prone 0.15, blended through `PM_StanceTransitionProgress`); times `BG_GetWeaponDef(ps->weapon)+0x264` when > 0; x0.4 if `cmd.buttons & 0x800`. Variants `PM_CmdScale2D` 0x080e1b1e, `PM_MaxAxisCmdScale` 0x080e1a02.
- `PM_PmTimeScale` 0x080e1f20 [obs]: `1 + t * (-minScale/maxTime)` using `ps->damageTimer (0x90)` and dvars `player_dmgtimer_minScale/maxTime`; 1 when either is 0.
- `PM_SlideMove` 0x080e9c42 [obs]: 4 bumps, 8 clip planes (abort at `numplanes >= 8`), CoD2-specific plane sorting by `dot(velocity,plane)` ascending (`PM_SortPlanesByDot` 0x080e9b7c), gravity half-step, writes `pml.impactSpeed (+0x5c)`. `PM_StepSlideMove` 0x080ea3f4: step size 18 (10 when `pm_flags & 1`, prone), step-up/down traces (down probe 9 units), emits event 0x8f (`stepDelta+0x80`, clamped -16..24), scales velocity by `(1 - |dz|/stepSize)*0.8 + 0.2`, step footstep bob advance. `Player_ClampJumpVelocity` is applied when a jump launched.
- `PM_GroundTrace` 0x080e38a2, `PM_CorrectAllSolid` 0x080e34c6 (26 offset directions at 0x081551e0, then airborne), `PM_GroundProbe` 0x080e36aa, `PM_CrashLand` 0x080e30c4 [obs details in 2.4], `PM_Trace` 0x080e1360 (retry without the 0x2000000 body bit after recording the touched entity via `PM_AddTouchEnt` 0x080e1474, 32 slots, entity 0x3fe ignored), `PM_TraceRaw` 0x080e1308 (pure dispatch).
- `PM_FreeMove`, `PM_FlyMove`, `PM_ClimbMove`, `PM_ReduceGroundSpeed` (minus 20 u/s while walking, clears at <=0) as above.
- `PM_SetMovementDir` 0x080e1f8c: `ps->movementDir` signed byte clamped to [-90, 90].

### 2.3 Stances (prone / crouch / stand)

[obs] State is split across `pm_flags` (bit 0x1 = prone, bit 0x2 = crouch, neither = stand), `ps->viewHeightTarget (0xf4)` (0x3c stand, 0x28 crouch, 0x0b prone), and `ps->eFlags` (bit 8 prone, bit 4 crouch; set in `PM_CheckDuck`, tested by the mantle gate). `PM_StanceIndex` 0x080e1532 maps `viewHeightTarget` to {0 stand, 1 prone (0x0b), 2 crouch (0x28)}.

`PM_CheckDuck` 0x080e4644 [obs]: sets `pm->mins/maxs` from `ps->mins/maxs` (0x56c/0x578) with `maxs[2] = 30` (prone), `50` (crouch), `ps->maxs[2]` (stand); dead/special pm_types get an 8x8x16 box (`mins -8`, `maxs 8,8,16`, flags cleared). Stance requests come from `cmd.buttons` 0x100 (crouch/stand) and 0x200 (prone) (observed tests, `0x300` also when on ladder); transitions to a taller stance are trace-tested (stand, crouch hull) and are denied when blocked; going prone probes a ledge via `PM_ProbeClimbableLedgeEntry` 0x080e0e58 (so prone cannot start where the body would end in geometry). Emits `0x8c/0x8d/0x8e` predictable events with params 0/1/2 on stance changes/failures (event semantics [unk]).

`PM_UpdateStanceHeight` 0x080e3eb0 [obs]: view height eases along piecewise-linear tables (12-byte rows `{percent, value, scalar}`, `-1` terminated): 0x08186780 (stand->crouch: 60,59.5,58.5,56,44,41.5,40.5,40 at 0,1,4,30,80,90,95,100), 0x08186800 (crouch->stand mirror), 0x08186880 (crouch->prone: 40,38,33,25,16,15,16,18 ... 0..70, rest not dumped), 0x08186960 (prone->crouch: 11,10,21,25,31,34,40 at 0,5,30,50,67,83,100). Transition durations `PM_StanceDurationMs` 0x080e3c46: 400 ms for any change to/from prone, 400 for crouch when toggle clear, else 200. Transitions also push velocity along the forward basis (velocity nudge). `ps->viewHeightLerpTime/Target/Down/PosAdj` (0xfc..0x108) carry the transition. Prone body yaw is limited by `bg_prone_yawcap` and eased by `PM_SmoothBodyAngles` (70 deg/s); ladder yaw cap `bg_ladder_yawcap`; mantle yaw cap `mantle_view_yawcap` (`Mantle_ApplyYawCap` 0x080de47a).

### 2.4 Jump, landing, ladder

- `Player_TryJump` 0x080dcca8 [obs]: blocked if `serverTime - ps->jumpTime < 500`, `pm_flags & 0x1000`, `pm_flags & 4` (mantling), `pm_type >= 6`, stance != stand; requires `cmd.buttons & 0x400` that was not set in `oldcmd.buttons` (else clears the bit). `Player_BeginJump` 0x080dca40: `v0 = sqrt(2 * gravity * jump_height)` (divided by the jump-speed factor if already in the jump slow-down phase), sets `jumpOriginZ = origin.z`, `jumpTime = serverTime`, `pm_flags |= 0x80000`, `pm_time = 0`, `velocity[2] = v0`, `aimSpreadScale += jump_spreadAdd` (cap 255), zeroes `pml.walking/groundPlane/groundTraceHit` (chunk_040 mislabels `pml` as `JumpMoveOut`), plays jump anim/event (0x5b on ladder else `0x46 + surfaceType`), and `BG_AnimScriptEvent(ps, 3|4, ...)`. From a ladder (`pm_flags & 0x20`) `Player_ApplyJumpPush` pushes away from `vLadderVec` with `jump_ladderPushVel`. The jump slowdown factor (`Player_JumpSpeedFactor` 0x080dc8ca) uses `pm_time` as phase (values 0x4b0 / 0x708 / 0x709 thresholds; `1 + t*1.5*0.000588` below 0x6a4 else 2.5) and `jump_slowdownEnable`.
- `PM_CrashLand` 0x080e30c4 [obs]: fall height from previous vertical velocity/gravity; damage rating 0..100 mapped between `bg_fallDamageMinHeight` (256) and `bg_fallDamageMaxHeight` (480) (error text "bg_fallDamageMaxHeight must be greater than bg_fallDamageMinHeight"); no damage if `groundTrace.surfaceFlags & 1` or `pm_type > 5`. Rating>0 and <100 and not slick: `pm_time = rating*35+500` (cap 2000), `pm_flags |= 0x200`, velocity scaled 0.5..0.2; else 0.67x. Events are `surfaceType + 0x18` (fall 4..8), `+1` (8..12), `+0x5d` (with heightBand, >12), `+0x74` (damage; param = rating). Landing also calls `BG_AnimScriptEvent(ps, 5, 0, 1)` when the fall is > 12 units.
- Ladders: `PM_CheckLadder` 0x080e805a traces forward (or opposite `vLadderVec`) with a shrunken box and requires surfaceFlags bit 8 on the hit; sets `pm_flags 0x20` and `vLadderVec`. `PM_Flags_EndLadder` 0x080e8026 sets `0x40000` if leaving a ladder. `PM_LadderMove` 0x080e847e. `PM_GetMoveSpeed` 0x080e9528 returns xy speed, or while on a ladder 0 for 500 ms after `jumpTime` then `velocity[2]`.

### 2.5 Mantle

[obs] Strings and registration confirm the mantle subsystem is IW's "mantle" (surface flags MANTLE_ON 0x2000000, MANTLE_OVER 0x4000000, mask 0x6000000 tested in `Mantle_FindSurface`). Flow, every pmove step when the player is not already mantling:

`Mantle_Debug(pm, &pml)` 0x080de088 (name wrong: it is the mantle attempt; it also prints "====== Mantle Debug ======") ->
1. needs `mantle_enable`, `pm_type < 6`, `pm_flags & 4 == 0`, `eFlags & 0xc == 0` (stance stand), `weaponstate` not in 0x11..0x16 (binoculars states [inf]).
2. `Mantle_FindSurface` 0x080dddfe: trace along the flat forward direction (`pml.forward` with z=0) from `origin - (r - radius)*dir` to `origin + (range + (r - radius))*dir`, box radius `mantle_check_radius`, content mask `0x1000000` [obs]; requires no start-solid/all-solid; surfaceFlags `& 0x6000000`; surface normal (negated, z=0) length >= 0.0001; angle between facing and normal <= `mantle_check_angle`.
3. `Mantle_CheckLedge` 0x080dd65a is tried at probe heights 60, 40, 20: checks 16 units forward clearance at height, traces down to find the ledge (`normal.z >= 0.7`), checks the player fits (crouched hull) on the ledge ("Player can't fit crouched on ledge"). If `cmd.buttons & 0x400` (the jump button) is also held, `Mantle_ComputeLedgeTarget` 0x080dd3dc + `Mantle_Start` 0x080dd552 begin the mantle; otherwise the check only sets `mantleState.flags |= 8` ("mantle available", used by the client for the hint [inf]).
4. `Mantle_Start`: `yaw = angle(ledge dir)`, `time = 0`, `stage = nearest of table[7]` to `ledge.ledgePos.z - ledge.start.z`, copies ledge flags, `origin = ledge.end - EvalStagePos(total)` (so the animation's root motion ends exactly at `ledge.end`), `pm_flags |= 4`, `eFlags |= 0x4000`, sets `pm->mantleActive(+0xe5) = 1`, `pm->mantleTarget(+0xe8) = ledge.end`, `pm->mantleEndHeight(+0xf4) = total duration (ms)`.
5. While `pm_flags & 4`: `Mantle_UpdateMove` 0x080de260 advances `mantleState.timer` by `pml.msec` (clamped to total), places the player at `origin += pos(newTime) - pos(oldTime)` where pos is the root translation of the xanim clips (up anim then over anim blended by time fraction), rotated by `mantleState.yaw`, sets velocity = delta/dt, drives `BG_AnimScriptAnimation(ps, 3, anim + 0x14, 1)`; at the end clears `pm_flags 4` and `pm->mantleActive`, plays `BG_AnimScriptEvent(ps, 3, 0, 1)` if over-flag, and with ledge flag 4 emits event 0x8c and clears `eFlags 0x4000`. Event 0x8d is emitted while flag 2 (hang) is set.
6. Server: `ClientThink_real` sees `pm.spawnEvent` and calls `G_SpawnPmoveEventEntity` 0x080f5c34, which spawns a short-lived temp entity (contents/clipmask 0x10000, svFlags 0x21, eType 5, owner = player, expires `time + level.time + g_mantleBlockTimeBuffer` (dvar default 500)). [inf] its purpose is to block other players from taking the mantle landing spot for the duration of the mantle (name `g_mantleBlockTimeBuffer` is observed in chunk 048 line 1551).

Mantle data [obs]: stage table at 0x08184d00 (`{up, over, zHeight}`): `{1,8,57},{2,8,51},{3,9,45},{4,9,39},{5,9,33},{6,10,27},{7,10,21}`. Animation names at 0x08184d60: `mp_mantle_root`, `mp_mantle_up_57/51/45/39/33/27/21`, `mp_mantle_over_high`, `mp_mantle_over_mid`, `player_mantle_over_low` (11 entries). The tree is `PLAYER_MANTLE` (global handle 0x08626fb0). `Mantle_ValidateAnims` 0x080ddaa4 (called from game init at 0x08109096, chunk_049) samples each clip's root translation and calls `Com_Error(1, "Mantle anim [%s] has X/Y/Z translation %f, should be %f")` unless: up anim translation X = 16 +-1, Y = 0 +-1, Z = stage height +-1; over anim X = 31 +-1, Y = 0 +-1, Z = -18 +-1. So the original `mp_mantle_*` clip data is required for correct durations (`XAnim_NodeDurationMs`) and motion; those numbers are NOT in the binary. [obs]

### 2.6 Weapon state shared with pmove (BG_ registry + PM_Weapon_*)

- Registry (chunk 043) [obs]: `bg_weaponDefs` pointer array at 0x086270a0 (136 entries), count at 0x08627080, ammo/clip/shared-cap type tables, item table at 0x081850c0 (stride 0x2c, giType@+0x1c, giTag@+0x20, 0x81 entries cleared in `BG_InitWeaponRegistry` 0x080eb7fc). Slot 0 is the "none" weapon returned by `BG_GetNoWeaponDef` 0x080f36d2. `BG_RegisterWeapon` 0x080ebc24 (loads through `BG_LoadWeaponDef`, chunk 045), error text "Couldn't find weapon "%s"", fallback `defaultweapon_mp`. Consistency checks fatally error on mismatched ammo caps/clip sizes/alt weapons ("Max ammo mismatch...", "Shared ammo cap mismatch...", "Clip Size mismatch...", "could not find altWeapon '%s' for weapon '%s'", alt weapon must not share `weaponSlot`).
- Ownership: `ps->weapons` 128-bit set at 0x544; held slots `ps->weaponslots[1..2]` (bytes at 0x555/0x556) with `BG_SetHeldSlot/TakeWeapon/FindWeaponSlot/PickStackableSlot` (chunk 043). `ps->ammo[128]` (0x144) is indexed by `ammoIndex`, `ps->ammoclip[128]` (0x344) by `clipIndex`; `BG_GetWeaponTotalAmmo` = clip + stock; `BG_ReloadClipFromAmmo` moves `min(stock, clipSize - clip)`.
- `PM_Weapon_Frame` 0x080f066e [obs]: skipped if `pm_flags & 0x1000`; if `pm_type >= 6` forces `ps->weapon = 0`; otherwise only when `eFlags & 0x300 == 0`: `PM_UpdateWeaponPosFrac`, `PM_UpdateTimer5b8` (hold-breath timer), offhand timer, `PM_Weapon_TickTimers` (decrements weaponTime/weaponDelay/etc.), button edges, offhand buttons, `ChangeSlot` (cmd.weapon vs `ps->weapon`), `UpdateInputState`, alt fire, `TryStartFire`, then the `weaponstate` switch [obs]: 1 -> ready; 2 -> `PM_Weapon_ChangeWeapon` (apply the pending weapon, gates: `pm_flags 0x20`, `0x4000000` script-disabled, held-set bit); 5/6 reload finish; 7/8 fire finish; 9 ready-alt; 10 -> 11 alt-fire; 11 ready; 12..16 offhand (grenade) sequence (enter 13/14/throw 15/16: events 0xa5, 0xa6, 0xa7, 0xc5, 0x94); 17..22 [inf] binocular/scope raise/hold/lower (these states gate mantle in 2.5; `pm_flags 0x20000` and `BG_GetCurrentWeapon` returning the first type-3 weapon); 0/3/4 fall through to `PM_Weapon_FireShot`. State names are numeric: only READY=0 and FIRING=3 are named by chunk 044 and only from transitions. Events `0x92` empty magazine, `0x95` ADS toggle sound, `0x96..0xa4` reload/raise/fire animation events (semantic names [unk]).
- `weaponMeter`/`aimSpreadScale` (0x5d4): float 0..255 maintained by `PM_Weapon_UpdateAttackMeter` 0x080ee9ee (view-angle delta/velocity driven) and advanced when firing/jumping; 255 when moving with prone flag or in alt-fire states.
- ADS/zoom: button 0x1000 -> `pm_flags 0x40` (`PM_UpdateWeaponFlag40` 0x080ecb42), `fWeaponPosFrac` approaches 1.0 (`PM_UpdateWeaponPosFrac` 0x080ecc9c), `player_adsExitDelay`, `player_toggleBinoculars`, `player_scopeExitOnDamage`; `PM_UpdateFlag100` sets `pm_flags 0x100` (slows move x0.4) while ADS-moving.

## 4. Data formats and protocols

- `playerState_s` network delta uses the 105-entry table at 0x08142520 (`MSG_WriteDeltaPlayerState` 0x0806a200 / `MSG_ReadDeltaPlayerState` 0x0806aaca). Entries `{name, offset, bits}`; `bits` 0 = float, -100 = float angle, negative = signed. I read the full table: it gives authoritative names for every networked pmove field (used to build `pmove.structs.json`). Fields with offsets 0x2c, 0x88, 0x8c, 0xc8, 0x5cc are not networked.
- Wire protocol for usercmd is owned by the net subsystem (`SV_UserMove` 0x08090e34 -> `SV_UpdateClientUsercmd` 0x08090dac -> `SV_GetClientUsercmd` 0x08091dda -> `client->cmd`). `CL_CreateCmd` 0x080689a6 (client side, present in the dedicated binary) shows the source mapping: `leanf` sign -> buttons 0x80/0x40, `eFlags` bits -> 0x100/0x200, `ps->0xd0/0xd4` -> `usercmd.offhand/weapon`.
- Usercmd button bits seen in pmove [obs, semantic names inferred]: 0x1 attack, 0x4 alt (melee/alt-fire per chunk 044), 0x40/0x80 lean left/right (also vertical in free-fly), 0x100 crouch, 0x200 prone, 0x400 jump (and mantle), 0x800 slow-walk, 0x1000 ADS, 0x2000 (`PM_CheckDuck`, [unk]), 0x10000/0x20000 offhand A/B, 0x40000 freeze/control-lock bit.
- Events: byte ring (4 entries) `events[]`/`eventParms[]`; ids seen in pmove: 0x46+surf (jump), 0x5b (ladder jump), 0x8b (foliage bump), 0x8c/0x8d/0x8e (stance/mantle), 0x8f (step), 0x92 (empty), 0x94-0x9d, 0xa0-0xac, 0xc5 (offhand throw), 0x01..0x5d ranges as `surfaceType + base` footsteps and landings. The server-side consumer is `Client_DispatchEvents` 0x080f52da / `G_HandleClientEvent`.
- `pm_flags` bit usage (`ps+0xc`) [obs, names inferred]: 0x1 prone, 0x2 crouch, 0x4 mantling, 0x10 offhand active, 0x20 on ladder, 0x40 ADS, 0x80 backpedalling, 0x100 ADS-moving slow, 0x200 landing slowdown, 0x400 knockback (no friction; set by `damage` in chunk 103 together with `pm_time = kickTime`), 0x800 prone-lock, 0x1000 weapon frame skipped / jump blocked (set on spawn, chunk 046 line 1129), 0x2000 alt-fire, 0x4000 hold-breath, 0x8000 controls frozen, 0x10000 set by `PM_CheckDuck` and cleared each step, 0x20000 scope/binocular weapon mode, 0x40000 just left ladder, 0x80000 airborne after jump, 0x400000/0x800000/0x1000000/0x2000000 session/spectator flags (chunk 046), 0x4000000 weapon disabled by script (`PlayerCmd_disableweapon` sets, `enableweapon` clears 0xfbffffff).

## 7. Behaviours a native port must reproduce

1. [obs] Sub-stepping: pmove time advances in steps of at most 66 ms, never more than 1000 ms behind `serverTime`; each step recomputes `pml.msec` as `clamp(serverTime - commandTime, 1, 200)`; `oldcmd` is overwritten after each step by the full `cmd` (with the intermediate `serverTime`). `ClientThink_real` clamps incoming `serverTime` to `[level.time - 1000, level.time + 200]`.
2. [obs] The movement order in `PM_SingleStep` (stance -> ground trace -> mantle attempt -> timers -> ladder/walk/air -> ground trace -> footsteps -> weapon frame -> bump check -> velocity fix-up -> snap) and the per-pm_type switch; the "velocity from origin delta" fix-up when the achieved squared speed is `< 0.25x` the pre-clip speed; `Sys_SnapVector` of velocity at the end of the normal path.
3. [obs] Float evaluation order matters: many helpers return x87 `long double` dot/length results (`DotProduct`, `VectorLength` via double `sqrt` then narrowing), `Q_roundToInt` = `floor(x + 0.5)`, `ROUND()` in pseudocode = `fistp` with truncation (control word 0xc00) per chunk 041. For bit-exact server parity use the same precision (double intermediate for the lengths, float storage for vectors) and truncating int casts.
4. [obs] Collision: player box from `ps->mins/maxs` with stance-specific `maxs[2]` (stand `ps->maxs[2]`, crouch 50, prone 30); step size 18 (10 when prone); `PM_SlideMove` multi-plane crease logic with plane sorting, 4 bumps, max 8 planes; `PM_ClipVelocity` overbounce 1.001; `PM_Trace` retry that strips the body bit 0x2000000 and records the touch entity; `PM_CorrectAllSolid` 26-direction nudge table (needs the 26 vectors at 0x081551e0; not dumped here).
5. [obs] Mantle: all constants in 2.5 (probe heights 60/40/20, 16-unit forward clearance, 18-unit ledge search up, 31-unit landing offset, `normal.z >= 0.7`, hull `maxs[2] = 50` at the landing check, stage table, anim root-translation offsets X16/X31/Z-18), jump button 0x400 as the trigger, `eFlags 0x4000` and `pm_flags 4` while mantling, no gravity/weapon movement during the mantle (only `Weapon_Frame`, `CheckDuck`), `mantle_enable` default 1.
6. [obs] Stance: hull sizes, view-height curve tables and 200/400 ms durations, tall-stance denial by trace, prone blocked by ledge probe, `PM_StanceIndex` from `viewHeightTarget`, eFlags 4/8.
7. [obs] Jump: `v0 = sqrt(2 g h)` with `h = jump_height (39)`; 500 ms re-jump window; `oldcmd` edge detection of button 0x400; jump slowdown/`jumpScale` friction coupling; apex clamp `Player_ClampJumpVelocity` (stops at `jumpOriginZ + jump_height`); landing damage mapping (256/480 default), landing slowdown timer `rating*35+500` ms (<= 2000) with `pm_flags 0x200`.

10. [obs] `BG_PlayerStateToEntityState` outputs (eFlags with 0x20000/0x40000 injected, prone torso blend, event replay with a 4-entry window) because the snapshot builder consumes them.
11. [inf] Preserve `ps` field offsets 0x2c (smoothed velocity), 0x88/0x8c (anim durations), 0xc8 and 0x5cc as private state; they are not networked.
