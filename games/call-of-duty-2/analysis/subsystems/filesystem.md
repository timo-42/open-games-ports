# Subsystem analysis: filesystem and archives (cod2_lnxded 1.3)

Target: `cod2_lnxded`, SHA-256 `05e774a3ee9fb487d4ec8a3d7d8d8e667f8ae459653e3c9e60a1c55604d5a3a7`, ELF32 i386.

Scope: `fs_*` search paths, iwd (zip) containers, the embedded zlib 1.1.4, the minizip-style reader, file I/O,
the `Sys_*` directory/home-path layer, and the localization string-table loader (`loc_*`, `.str` files).

Evidence tags: **[O]** observed (string, disassembly or pseudocode read directly), **[I]** inferred (consistent
reading, not directly proven), **[U]** unknown. Addresses are virtual addresses in the binary.

Evidence base and limits:
- The reconstructed chunks (`recon/chunks/chunk_NNN.cpp` and `_types.h`) for chunks 6, 7, 8, 21, 23, 24, 25, 35, 36, 37, 38,
  59, 60, plus the later chunks 100, 101 and 102 (finished json, not yet merged into `symbols.json`).
- `objdump -d -M intel` of the binary. This was used to verify struct offsets and call sites where chunks disagree.
  REA and Ghidra were not opened, per the task rules. No REA Evidence IDs were generated by this analysis.
- Ghidra pseudocode under `.local/cod2/decomp/functions/` was read for `FS_FOpenFileReadInternal` (0x0809f958),
  `FS_LoadPackFile` (0x080a0d5e) and the function at 0x0805228e.
- Nothing was run. No real iwd files were opened. All behaviour statements are static-analysis conclusions.
- Callers were computed by scanning direct `call rel32` instructions only. Indirect calls (function pointers, vtables) are
  invisible, so "no callers" means "no direct callers".
- `symbols.json` lacks several function boundaries in this area (see Naming problems), so a naive caller attribution is
  wrong in places. Attribution here was corrected by hand.

## 1. Purpose and architecture as implemented in THIS binary

This is a Quake III-lineage virtual filesystem **[I]** with Infinity Ward changes:

- A singly linked **search path list** (`fs_searchpaths`, 0x0849fd68). Each node is either a loose directory
  (`fs_directory_s`) or a loaded **iwd** (renamed pk3, standard zip) **[O]**.
- Each iwd is indexed once at load time. The zip central directory is read, every entry name is lower-cased and put in a
  power-of-two hash table of chained entries (`FS_LoadPackFile` 0x080a0d5e). File reads then go through a hand-linked
  minizip (`unz*`, 0x080d1bfc-0x080d3597) on top of zlib 1.1.4 raw inflate **[O]**.
- A 64-slot **file handle table** (`fs_handles`, 0x0849fd80, stride 0x11c, slot 0 invalid) handles both loose files
  (`FILE*`) and pack entries (`unz_s*`) **[O]**.
- A **pure server** layer: `fs_serverIwds` and `fs_serverIwdNames` are an allow-list of iwd checksums and names. When the list
  is non-empty, only the listed iwds (and localized iwds) are searched, and loose files are restricted to a few extensions **[O]**.
- A **localization layer** specific to CoD2 **[O]**:
  - 15 languages. Localized iwds are named `localized_<language>_*.iwd`; localized loose directories are `<gamedir>/<language>/`.
  - Search path nodes carry a `localized` flag and a `language` index, and only the nodes of the current
    `loc_language` are visible (`FS_SearchPathAllowed` 0x0809e6a0).
  - `.str` files under `localizedstrings/` are parsed into an in-memory `std::map<string,string>`.
- The dedicated server is a stripped build of the client engine. Many FS entry points exist in the binary but have no direct
  callers on the server (see section 3).

Lineage: nearly every function has a direct id Tech 3 counterpart (`FS_FOpenFileRead`, `FS_ListFilteredFiles`, `FS_Startup`,
`FS_Restart`, `Sys_ListFiles`...). Names above come from the chunks and were checked against behaviour. Where lineage and
behaviour disagree, behaviour wins (see sections 4 and 8).

## 2. Entry points and call flow

### 2.1 Initialisation (once, at Com_Init)

`Com_Init_Try_Block_Function` 0x080620c0 -> `FS_InitFilesystem` 0x080a325a **[O: direct call]**:

1. `Com_StartupVariable` for `fs_cdpath`, `fs_basepath`, `fs_homepath`, `fs_game`, `fs_copyfiles`, `fs_restrict`, `loc_language`
   (command-line `+set` overrides) **[O]**.
2. `Loc_RegisterDvars` 0x08138162 registers the loc dvars.
3. `FS_Startup("main")` 0x080a2de0 (below).
4. `Loc_CallA` 0x081383ee = `LocTable_Create` 0x0813a768, which allocates the global string table. Then `Loc_InitLanguages` 0x08138224.
5. `FS_SetRestrictedDemoMode` 0x08065848. If `fs_restrict`, it calls `FS_Shutdown` and `FS_Startup("demomain")`, and every
   allowed iwd must have checksum `0xB1F595F5` (`-0x4e0a6a0b` in the code), otherwise `Com_Error(0, "Corrupted iw0.iwd: %u")` **[O]**.
6. `FS_ReadFile("default_localize_mp.cfg")`. If the result is below 1, it tries `default_mp.cfg`. If that also fails,
   `Com_Error(0, "Couldn't load %s.  Make sure Call of Duty is run from the correct folder.", "default_localize_mp.cfg")`.
   The winning name is stored in `fs_defaultConfigName` (0x0849fc28) **[O]**.
7. `fs_basepath` and `fs_game` are saved into `fs_savedBasePath` and `fs_savedGame` (0x084a84c0, 0x084a85c0) **[O]**.

### 2.2 FS_Startup (0x080a2de0)

Prints `----- FS_Startup -----`, zeroes `fs_iwdFileCount`, calls `FS_RegisterDvars` (0x080a2c3c, once-only, guarded by `fs_debug`
being NULL). Then it adds game directories. **Each add inserts at the head**, so later adds have higher priority **[O]**.
Order of addition (`G(base, name)` = `FS_AddGameDirectory_080a2a10(base, name)`):

1. If `fs_useOldAssets`: `G(basepath,"tempcod")`, `G(homepath,"tempcod")`.
2. `devraw_shared`, `devraw`, `raw_shared`, `raw` for basepath, then homepath, then cdpath (each only if the path is non-empty).
3. `G(cdpath, gameName)`, `G(basepath, gameName)`, `G(homepath, gameName)` (homepath only if it differs from basepath, `Q_stricmp`).
4. If `fs_basegame` is set, `gameName == "main"` and `fs_basegame != "main"`: cdpath, basepath, homepath (if different) of `fs_basegame`.
5. If `fs_game` is set, `gameName == "main"` and `fs_game != "main"`: same three for `fs_game`.
6. `FS_AddCommands` (0x080657dc; `path`, `fullpath`, `dir`, `fdir`, `touchFile`), `FS_PrintPureSearchPaths`,
   `Dvar_ClearModified(fs_gameDvar)`, prints `%d files in iwd files`.

Net priority, highest first: fs_game (home, base, cd), fs_basegame, main (home, base, cd), raw dirs, devraw dirs, tempcod **[I, derived from the order]**.
Within one game directory, iwds beat the loose directory (the dir node is inserted first, then the iwds are inserted above it) **[O]**.

`FS_AddGameDirectory_080a2a10` (0x080a2a10) loops `language = 14..0` calling `FS_AddGameDirectory(path, dir, 1, language)`, then
`FS_AddGameDirectory(path, dir, 0, 0)`. The loop index is a **language index**, not an "iwd slot number" as the chunk 25 comment says **[O]**:
`FS_AddGameDirectory` 0x080a27ae passes it to `LocLanguage_Name`.

`FS_AddGameDirectory` (0x080a27ae):
- The directory name is `dir` (truncated to 63 characters) or `dir/<languagename>` for localized adds.
- A duplicate (same path and gamedir, case-insensitive) is not re-added. It warns if the localized flag or language differs
  (message spelling `game golder` is in the binary).
- A localized directory is only added if `Sys_DirectoryHasContent` (0x080d6886) is true for it.
- A non-localized add stores the name into `fs_gamedir` (0x0849fc40). The last non-localized add wins, which makes the
  **write directory** the last game directory added (normally `fs_game`, else `main`) **[O]**.
- It then calls `FS_AddIwdFiles(path, name)`.

`FS_AddIwdFiles` (0x080a241c):
- Lists `*.iwd` (`Sys_ListFiles`, max 0x400 files, warning above that).
- Names starting with `localized_` have that prefix overwritten with 10 spaces so the qsort comparator
  `FS_CompareLocalizedIwd` (0x080a22ee) can order them. Localized names sort first; among localized, `english` first, then `FS_PathCmp`.
- Each iwd is then loaded in sorted order. Localized names must parse as `localized_<language>_...`:
  - an empty language gives a warning and the iwd is skipped;
  - an unknown language gives a warning, prints "Supported languages are:" once, and skips the iwd;
  - otherwise the iwd is added as localized with the language index.
- `FS_LoadPackFile(path, name)`, `pack->pakGamename = gamedir`, a 0x14-byte node, `FS_InsertSearchPath`.

`FS_InsertSearchPath` (0x080a23d4), verified by disassembly **[O]**: non-localized nodes go at the head. Localized nodes go after the
leading run of non-localized nodes. Invariant: all non-localized nodes precede all localized nodes. **Localized assets therefore have the
lowest priority; any non-localized directory or iwd hides a localized file of the same name.**

### 2.3 Restart (map change)

`SV_SpawnServer` 0x08093520 calls (in this order) `FS_Shutdown(1)`, `FS_ClearPakReferences`, `Com_Restart_Subsystems`, generates
`sv.checksumFeed = Sys_Milliseconds ^ (rand()<<16) ^ rand()`, then `FS_Restart(sv.checksumFeed)` **[O, chunk 21 source]**.

`FS_Restart` (0x080a337a):
1. `FS_Shutdown`.
2. `fs_checksumFeed = checksum` (0x0849fd74).
3. `FS_ClearPakReferences`.
4. `FS_Startup("main")`, `Loc_CallA`, `Loc_InitLanguages`, `FS_SetRestrictedDemoMode`.
5. Read `fs_defaultConfigName`. If it cannot be read and a saved base path exists: `FS_PureServerSetLoadedIwds("","")`, restore
   `fs_basepath`, `fs_game` and `fs_restrict`=0, recurse once, then `Com_Error(1, "Invalid game folder\n")`. Otherwise `Com_Error(0, "Couldn't load %s...")`.
6. If `fs_game` changed from the saved value and `Com_SafeMode()` is false: `Cbuf_AddText("exec config_mp_server.cfg\n")`.
7. Update the saved base path and game.

`FS_Shutdown` (0x080a2ba8): `Loc_CallB` (= `LocTable_Destroy`), closes every handle slot 1..63 whose **+0x0c field is non-zero**
(see section 5.1), `FS_FreePakList` (closes each unz, frees index, pack, node and dir), sets `fs_searchpaths = NULL`, removes the five
commands. It ignores its argument (callers pass 0 or 1) **[O]**.
Not reset by `FS_Shutdown`: `fs_serverIwds`, `fs_numServerIwds`, `fs_checksumFeed` (set by Restart), `g_0849fd70`.

`FS_ConditionalRestart` (0x080a34fe): no direct callers in this binary **[O]**. Likely client-only **[I]**.

### 2.5 Pack open path: FS_FOpenFileReadInternal (0x0809f958)

Two wrappers call it: `FS_OpenFileRead` 0x080a0266 (quiet=0, also sets `g_0849fc20 = 1`) and `FS_FOpenFileRead_Quiet` 0x080a0236 (quiet=1,
no direct callers) **[O]**. Signature `(filename, int *file, int uniqueFile, int quiet)`.

1. `FS_SanitizeQpath` (0x0809f7a0): strips leading separators, collapses separator runs to one `/`, drops `.` components, and **rejects the
   whole path if `..` or `::` occurs anywhere** (not only at component starts). Returns -1 and sets `*file = 0`.
   The output buffer size is not checked **[O]**. A native port must bound it.
2. If `file == NULL`: existence probe only. Returns 1 or -1, no handle used, no side effects on `referenced`.
3. Otherwise `h = FS_HandleForFile(quiet)`. `*file = h`. `fs_handles[h].uniqueFile = uniqueFile`.
   **Slot range is selected by `quiet`**: quiet=0 uses slots 1..50, quiet=1 uses slots 51..63 (0x33..0x3f) **[O]**.
4. Walk `fs_searchpaths` in order, skipping nodes for which `FS_SearchPathAllowed` is false.
   - **Loose directory node** (or a pack node whose hash bucket is empty, in which case `dir` is NULL and nothing happens):
     - Loose files are considered only if `(!fs_restrict && !fs_pureEnabled) || search->localized || extension is unrestricted`.
       Unrestricted extensions are `cfg`, `menu`, and a dead literal `.dm_NETWORK_PROTOCOL_VERSION` (leading dot makes it unmatchable,
       a macro stringification bug in the original) **[O]**.
     - On success: if the node is non-localized and the extension is restricted, `g_0849fd70 = rand() + 1`. If `fs_copyfiles` and the dir is
       `fs_cdpath`, the file is copied to `fs_basepath` (`FS_CopyFile`). Returns `FS_filelength(h)`.
     - If not allowed but the file exists: remembers `restrictedFound`.
   - **Pack node**: hash the lower-cased name, walk the bucket comparing with `FS_FilenameCompare`. On a match:
     - Allowed if `search->localized || FS_ChecksumAllowed(pack)`. A non-allowed match records `unpurePack` and moves on.
     - If `!pack->referenced && !FS_HasTextAssetExtension(qpath)`, set `pack->referenced = 1`. Text-like extensions
       (`.hlsl .txt .cfg .levelshots .menu .arena .str`) do NOT mark a pack as referenced **[O]**.
     - `uniqueFile == 0`: the handle shares `pack->handle` (a single unz reader per pack).
       `uniqueFile != 0`: `unzReOpen` clones the reader with its own `FILE*` (error `Couldn't reopen %s`, or return -1 if quiet).
     - `unzSetOffset(pack->handle, entry->filePos)`, copy the 0x80-byte state into the private reader (keeping its own first word =
       the `FILE*`), `unzOpenCurrentFile`. Returns the entry's uncompressed size from the unz state at +0x44.
5. Not found: `*file = 0`. If `unpurePack`: `Com_Error(1, "EXE_UNPURECLIENTDETECTED\x15\n%s", pack file)`. Returns -2 if a restricted
   loose file exists, else -1.

Result codes: size >= 0 found, -1 not found, -2 found but blocked by restriction **[O]**.

### 2.6 Read, write, seek

- `FS_Read` (0x080a052a): pack handle -> one `unzReadCurrentFile` call (short reads possible, returns negative on zlib error). Loose handle ->
  `fread` loop; two consecutive zero-byte reads end the loop and return the partial count. A `-1` from fread raises
  `Com_Error(0,"FS_Read: -1 bytes read")` except for slots 0x33..0x3f which return -1 **[O]**.
- `FS_Write` (0x080a0656): `fwrite` loop (same two-zero rule, returns 0 on failure), `fflush` if `handleSync` **[O]**. There is no pack-handle check.
- `FS_ReadFile` (0x080a0a9c): empty name is `Com_Error(0,"FS_ReadFile with empty name\n")`. With `buffer == NULL` it only measures. Otherwise
  `Hunk_AllocateTempMemory(len+1)`, read, NUL-terminate, `fs_loadStack++`. `FS_FreeFile` does `fs_loadStack--` and
  `Hunk_FreeTempMemory`. Returns -1 and `*buffer = NULL` when not found **[O]**.
- `FS_Seek` (0x080a078a): for pack handles, seeking backwards re-opens the entry (`unzSetOffset` + `unzOpenCurrentFile`), then forward-skips by
  `unzReadCurrentFile(zip, NULL, n)`. `FS_SEEK_CUR=0, END=1, SET=2` in this engine's enum **[O]**. The NULL-buffer skip works because the
  embedded zlib `inflate_flush` guards `memcpy` with `if (q != NULL)` (0x080ce864) **[O]**. For stored (method 0) entries `unzReadCurrentFile`
  writes into `next_out[i]` unconditionally, so a NULL skip on a stored entry would fault. Unknown whether any iwd entry is stored **[U]**.
- Write targets are always `fs_homepath/fs_gamedir/<qpath>` (`FS_FOpenFileWrite` 0x0809efe0, `Append` 0x0809f1dc, `WriteText` 0x0809f08a,
  `FS_WriteFile`, `FS_CopyFile`, `FS_Rename`, `FS_DeleteFile`) **[O]**. `FS_CreatePath` (0x0809eae0) refuses `..` and `::` and creates parent
  directories with `mkdir(path, 0777)` (`Sys_Mkdir` 0x080d5ee4).
- `FS_BuildOSPath` (0x0809e9b6): `base/game/qpath`; empty `game` falls back to `fs_gamedir`; total length limit 255 else
  `Com_Error(0, "\x15FS_BuildOSPath: os path length exceeded\n")`; then collapses separator runs via `FS_ReplaceSeparators` **[O]**.
- `FSH_FOpenFile` (0x080a3562), the high-level opener used by scripts and bans: modes 0 read (`FS_OpenFileRead(...,unique=1)`), 1 write,
  2 append, 3 append+sync. Bad mode: `Com_Error(0,"FSH_FOpenFile: bad mode")`. See section 5.1 for what it stores.

### 2.7 SV-side direct FS (outside the search path)

`FS_SV_FOpenFileRead` (0x08064558), `FS_SV_FOpenFileWrite` (0x080643e8), `FS_SV_Rename` (0x08064878), `FS_SV_FileExists` (0x08064358). They build
`base/<filename>` (the file name takes the "game" slot, the qpath is empty, and the trailing `/` is stripped). Read order: `fs_homepath`, then
`fs_basepath` (if different), then `fs_cdpath`. `fs_debug` gates the log lines **[O]**. Quirk kept in the code: after the basepath attempt fails,
`handle` is reset to 0 and the following existence check / `cdpath` store operate on slot 0 **[O]**.

### 2.8 Listing

`FS_ListFiles` 0x080a19bc -> `FS_ListFilteredFilesInList` 0x080a13bc. Extension `"/"` means directories only. Results are de-duplicated case-insensitively
(`FS_AddFileToList`, cap 0xfff entries), unsorted. Loose directories are listed through `Sys_ListFiles`. Pack entries are matched by directory depth and prefix.
Loose directories are only listed if `(!fs_restrict && !fs_pureEnabled) || allowNonPure`. Packs are included if `localized || FS_ChecksumAllowed`.
`fdir` (`FS_NewDir_f`) sorts with `FS_SortFileList` and `FS_NormalizeSeparators`. `FS_GetModList` 0x08064bcc lists mod directories. The two-argument
chunk-24 function 0x080a1d4a is really `FS_GetFileList` (path, extension, ..., out buffer; `$modlist` delegates to `FS_GetModList`) **[O]**.
The trailing integer passed to `FS_ListFiles` (3, 10) and `FS_FreeFileList` (10, 3) is read by nobody **[O]**.

## 3. Reachability on the dedicated server (direct callers only)

No direct callers **[O]**, so likely dead or indirect on the server: `FS_ConditionalRestart`, `FS_SetIwdChecksums` 0x08065f94, `FS_BuildMissingIwdList`
0x080654a0, `FS_ReferencedIwdPureChecksums`, `FS_LoadedIwdPureChecksums`, `FS_FOpenFileRead_Quiet`, `FS_FTell`, `FS_Rename`, `FS_SV_Rename`, `FS_SV_FOpenFileWrite`,
`FS_FileCompare`, `FS_ShiftedKeyProbe`, `FS_SetOwnerReadBit`, `FS_LocateLooseFile`, `FS_LooseFileGamePath`, `FS_ListFilesByGameMask`,
`FS_HasLoadedPakWithId` (called by `Loc_InitLanguages`, so reachable), `FS_ReadThroughHandle` 0x080649cc, `Dir_HasNonDotEntries`,
`Sys_FileTime`, `Sys_DefaultInstallPath`, `zlib_uncompress`, `compress`/`compress2`/`deflate*` (statically linked zlib).
`FS_Seek` and `FS_Read` are reachable. `Sys_Fread` and `Sys_Fseek` only forward to them.

A native server port can omit the "no direct callers" set unless a client or a tool path is wanted.

## 5. Data formats and protocols

### 5.1 File handle table (0x0849fd80, stride 0x11c, 64 slots) **[O]**

| Offset | Field | Evidence |
| --- | --- | --- |
| 0x00 | `handle`: `FILE*` for loose files, `unz_s*` for pack entries | `FS_FileForHandle` returns it |
| 0x04 | `uniqueFile`: pack entry opened with its own reader | `FS_FOpenFileReadInternal` writes arg 3 |
| 0x08 | `handleSync` | `FS_Write`, `FSH_FOpenFile` writes 0x849fd88 |
| 0x0c | `fileSize` (only written by `FSH_FOpenFile`, read by `FS_Shutdown` as "in use") | |
| 0x10 | `zipFilePos` | `FS_Seek`, `FS_FOpenFileReadInternal` |
| 0x14 | `pack` (non-NULL = pack entry) | |
| 0x18 | `streamOpen` | `FS_FCloseFile`, `FS_Seek`, `FS_ReadThroughHandle` |
| 0x1c | `name[256]` | `FS_HandleForFile` dump `FILE %2i: '%s'` |

Slot allocation: `FS_HandleForFile(quiet)` scans 50 slots from 1 (quiet=0) or 13 slots from 0x33 (quiet=1) for `handle == NULL`. None free dumps all names and
`Com_Error(1, "\x15FS_HandleForFile: none free")` **[O]**.

`FS_Shutdown` closes only slots whose `fileSize` field is non-zero. `FSH_FOpenFile` sets `fileSize = result`, which for read opens is the
length, for write/append opens is 0. So handles opened for writing (including the log file, config writes) and zero-length reads are NOT closed
by `FS_Shutdown`. Also `FSH_FOpenFile` writes `handleSync` even when `*fileHandle == 0` (touching slot 0) **[O]**.

The `streamOpen` flag is only ever set to 1 transiently inside `FS_ReadThroughHandle` and `FS_Seek`, and cleared at every open. So at rest it
is always 0 and the `Sys_Fread`/`Sys_Fseek`/`Sys_NoOp_080d4754` stream layer is inert in this binary **[O]**. Its original purpose is unknown **[U]**.
Note `FS_Seek` with `streamOpen != 0` seeks twice (the hook, then the normal path) **[O]** (cannot trigger here).

### 5.2 iwd / zip container

- iwd is a plain zip. Reader: `unzOpen` 0x080d1f69 finds the end-of-central-directory signature by scanning back at most 0xffff bytes, in
  0x400-byte blocks (buffer 0x404). Validates that the disk numbers are 0 and the entry totals match; `central_pos` must not be below
  `offset_cd + size_cd`; sets `byte_before_the_zipfile = central_pos - (offset_cd + size_cd)`. There is no zip64 and no multi-disk support **[O]**.
- Entry iteration: `unzGoToFirstFile`, `unzGoToNextFile`, `unzGetCurrentFileInfo` (name limit 0x100), `unzGetOffset` (central dir
  position as the file's "filePos"), `unzSetOffset`, `unzLocateFile` (unused here) **[O]**.
- `unzOpenCurrentFile` 0x080d2e9e: `unzlocal_CheckCurrentFileCoherencyHeader` validates the local header against the central entry. It allocates
  0x64 bytes + a 0x4000 read buffer. If the method is not 0 it starts `inflateInit2_(-15, "1.1.4", 0x38)`. The binary computes a
  "bad method" status for methods other than 0 and 8 into a dead local and opens anyway **[O]**.
- `unzReadCurrentFile` 0x080d3094: refills 16 KiB chunks, copies stored entries directly, uses `inflate(Z_SYNC_FLUSH)` for deflated ones.
  **No CRC32 is computed or checked anywhere** (there is no `crc32` function in the binary; `adler32` is present only for zlib streams) **[O]**.
- Pack checksum (`FS_LoadPackFile`): collect the zip-header CRC32 of every entry with `uncompressedSize != 0` (directories and empty files excluded)
  into an int array. `checksum = Com_BlockChecksum(crcs, n*4)` (MD4 over the buffer, XOR of the four digest words; 0x08067b02) and
  `checksumPure = Com_BlockChecksumKey(crcs, n*4, fs_checksumFeed)` (0x08067b5e, the same with a 4-byte key hashed first). `Int_Identity` (0x080a3748, LittleLong)
  wraps the values. Note `checksumPure` is computed from the feed at **load** time, so the feed must be set before the packs load (that is why
  `FS_Restart` sets it first) **[O]**.
- Index structure: `numEntries * 12 + sum(strlen(name)+1)` bytes of entries and names, hash table size = smallest power of two greater than
  `numEntries`, capped at 0x800 (the loop condition `hashSize < 0x401 && hashSize <= n`), allocated after the 0x320-byte pack header.
  Names are lower-cased with `Q_strlwr`. Each chain is LIFO (the last entry added is first in the bucket). Duplicate names in one zip: the later central-directory entry wins **[O]**.
- Hash function (0x0809e740): over the lower-cased name, stopping at the first `.`; `\` maps to `/`; `hash += (i + 119) * c`; result
  `((hash >> 20) ^ (hash >> 10) ^ hash) & (size - 1)`. The same hash is used by the hunk user-entry table (`Hunk_AddUserEntry`) **[O]**.
- `FS_FilenameCompare` (0x0809f32c): equal-ignoring-case with `\` and `:` equal to `/`. Returns 0 for equal, -1 otherwise **[O]**.

Official iwd recognition (`FS_iwIwd` 0x08065324): `<base>/iw_00..iw_24` or `<base>/localized_<...>` containing `_iw00.._iw24`. Used by the download
code to refuse official files. `FS_IwdNameHasSvrMarker` 0x08065450 matches a lower-cased `_svr_` **[O]**.

### 5.3 Checksum list protocol (server -> client)

- `sv_iwds` (loaded checksums, **only if `sv_pure`**): `FS_LoadedIwdChecksums` = `"%i "` of `pack->checksum` for every pack node whose **localized flag
  (+0x0c) is 0** (chunk 7 mis-read this as `dir == 0`; disassembly 0x08065935 tests +0x0c) **[O]**.
- `sv_iwdNames`: space-joined pack basenames (no game dir, no extension) of the same set.
- `sv_referencedIwds`: `pack->checksum` of packs with `referenced != 0` **or** a pack whose game name does not start with `main` (case-insensitive,
  4 chars) i.e. mod iwds are always "referenced". `sv_referencedIwdNames`: `gamename/basename` tokens for the same set **[O]**.
- Client-side (unreached on this server): `FS_ReferencedIwdPureChecksums` builds `"@ "` + `"%i "` of `checksumPure` for referenced packs, then optional
  `g_0849fd70`, then `checksum ^ count` where `checksum` starts as the feed XOR-ed with each pure checksum **[O]**.
- `FS_PureServerSetLoadedIwds(sums, names)` (0x08065d9a): tokenises both strings (max 0x400 each); a count mismatch is `Com_Error(1,"iwd sum/name mismatch")`.
  If identical to the current list nothing changes. Otherwise it replaces `fs_serverIwds`/`fs_serverIwdNames`; for a non-empty list it prints
  `Connected to a pure server.` (developer print) and zeroes `g_0849fd70`.
- `FS_ChecksumAllowed(pack)` (0x0809e638) returns 1 when `fs_numServerIwds == 0`, else true iff `pack->checksum` (**+0x304, the non-pure checksum**) is in `fs_serverIwds`.
  So the allow-list holds non-pure checksums, unlike Q3 **[O]**.

### 5.4 Localized string tables (`.str`)

Load (`LocTable_LoadAll` 0x0813a81e, called via `Loc_LoadLanguage` 0x0813840a from `Loc_InitLanguages`):
- `LocTable_ResetCurrent`, then `FS_CollectLocalizedFiles("localizedstrings", &list)`: a recursive `FS_ListFiles(dir,"/")` (skipping names starting
  with `.`) plus `FS_ListFiles(dir,"str")`, building a `;`-separated list of `dir/file.str` paths; then `LocList_NextEntry` pops entries (63 characters max
  each) and `LocTable_LoadFile` parses each. Stops at the first error and returns its message string.
- **Language is not a parameter of the loader.** It is implicit in the search path: only nodes with `localized == 0` or `language == loc_language`
  are visible (`FS_SearchPathAllowed`). `loc_forceEnglish` is passed as `english_only`, which makes the parser skip non-English `LANG_` lines **[O]**.
- File format (line based, `//` comments stripped outside quotes, trailing whitespace trimmed; CR/LF tolerated):
  `VERSION "1"` (any other value: `Unexpected version number %d, expecting %d!`), `CONFIG`, `FILENOTES`, `NOTES`, `FLAGS` (ignored), `REFERENCE <KEY>` (declares
  `<FILEBASE>_<KEY>` with an empty value and makes it the current key), `LANG_<LANGUAGE> "text"` (sets the value of the current key; English also records
  `last_english`; a non-English value of `#same` copies the last English text), `ENDMARKER` (a file without it fails with
  `Truncated file, failed to find "ENDMARKER" at file end!`). Other lines: `Unknown keyword at linestart: "%s"`.
  Values: leading blanks and one opening quote removed, trailing blanks and one closing quote removed, literal `\n` (two chars) replaced by a newline.
  `&&<digit>` placeholders may each occur once (`Illegal string format` otherwise). `LANG_` before any `REFERENCE` is `Error parsing file: Unexpected "LANG_"` **[O]**.
- Keys are `UPPER(<file base name without extension>)_<key>`. `Loc_TranslateString(s)` looks up `s` verbatim (no prefix), so callers pass the full
  `FILEBASE_KEY` form. Returns the input unchanged if `loc_translate` is off or `strlen(s) < 2`; **returns NULL when the key is missing**, which callers
  of `Loc_TranslateString` must handle. `Loc_TranslateExeString` and `Loc_TranslatePart` add the `^1UNLOCALIZED(^7...^1)^7` wrapper and honour
  `loc_warnings`/`loc_warningsAsErrors` (error code 6) **[O]**.
- The container is a `std::map<std::string,std::string>` (libstdc++ 3.x COW string, red-black tree, node 0x18 bytes) **[O]**. Iteration order is key order.
- `Loc_InitLanguages` 0x08138224: marks `available` for each of the 15 languages with `FS_HasLoadedPakWithId(i)` (any localized node for that language), prints
  `^1ERROR: No languages available because no localized assets were found` when none, tries `loc_language` then every language 0..14 until one loads,
  finally resets to 0. `Loc_UpdateDoubleByteFlag` sets the double-byte flag for `loc_language` 8..12 **[O]**.
- Double-byte character classification (`LocText_ReadChar` 0x08138e64): 8 EUC-KR/Hangul, 9 Big5, 10 Shift-JIS, 11 a 0x8140-based DBCS (code page not identified);
  otherwise single byte. Used by `LocText_CountVisibleChars`. Display-only, no server effect **[O]/[U]**.

### 5.5 Error-text convention

Many `Com_Error` strings begin with the byte `0x15` (for example `"\x15FS_BuildOSPath: os path length exceeded\n"`, `"EXE_UNPURECLIENTDETECTED\x15\n%s"`).
The `EXE_*` names are keys of the localized string table. The meaning of `0x15` inside `Com_Error`/`Com_Printf` is unknown here **[U]**;
`SV_WriteDownloadToClient` uses the same `EXE_...\x15<arg>` shape for client-visible messages **[O]**.

## 8. Behaviours a native port must reproduce

1. Case-insensitive name matching where `\` and `:` equal `/` (`FS_FilenameCompare`), lower-cased names in the index, and `FS_SanitizeQpath` rejection of any
   `..` or `::` substring plus its leading-separator and `.`-component removal.
2. Search path construction order, the head-insert rule, and the localized-node placement (section 2.2). Within one game directory, iwds in
   ascending sorted order are inserted so that the **last sorted name is highest priority**; localized names are sorted first.
3. Loose-file restriction rules (`fs_restrict`, active pure list, localized exemption, extensions `cfg` and `menu` always loose), including result codes -1 and -2 and the
   `EXE_UNPURECLIENTDETECTED` error when a file is only present in a non-allowed pack.
4. The `referenced` bit semantics (text-asset extensions do not mark packs) and the checksum strings given to clients (section 5.3), including the exclusion of
   localized packs from `sv_iwds`/`sv_iwdNames`, the inclusion of mod packs (game name not starting with `main`) in the referenced lists, and the CRC-list
   checksum (zero-size entries excluded, MD4 XOR).
5. Pack checksum timing: `checksumPure` depends on the feed present at load time.
6. Handle slot partitions (1..50 and 51..63), the 64-slot limit and its fatal error, handle 0 meaning "none", the `FS_Read` short-read loop and the
   partial-return behaviour on two zero reads.
7. Pack entry opening: shared vs unique reader semantics (`FSH_FOpenFile` read = unique; `FS_ReadFile` = shared), and `FS_Seek` backward reopen.
8. The write directory rule: always `fs_homepath/fs_gamedir` where `fs_gamedir` is the last non-localized game directory added.
9. Zip parsing leniency: no CRC verification, no method validation, EOCD scan window 0xffff, no zip64. Add bounds checks that the original lacks without changing
   accepted-input behaviour (name buffers are 0x100, `FS_SanitizeQpath`'s output is unbounded, `FS_FOpenFileReadInternal` uses 268/256/271-byte stack buffers).
10. Listing semantics (dedupe, cap 0xfff, depth matching, `/` for directories, `.`/`..` entries included by `Sys_ListFiles` for directory listings) and `Sys_ListFiles` extension match by suffix without the dot.
11. Home directory `$HOME/.callofduty2` creation; basepath default = cwd; `fs_copyfiles` cdpath to basepath copying.
12. Localization file format, key prefixing, `loc_language` filtering via search paths, `#same` copying, error message texts, NULL result for missing keys, and
    `loc_translate` short-circuit.
13. `FS_Restart` side effects: re-run `exec config_mp_server.cfg` when `fs_game` changes, saved base/game restore on a missing default config, `Invalid game folder`.
14. The map/asset path convention `maps/mp/<name>.d3dbsp`, `<script>.gsc`, `localizedstrings/*.str`, `ban.txt`, `default_localize_mp.cfg`/`default_mp.cfg`,
    `console_mp_server.log`.
