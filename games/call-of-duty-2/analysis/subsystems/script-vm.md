## 1. Purpose and architecture

[O] The server executes GSC as bytecode in a stack VM that is statically linked into `cod2_lnxded` (no separate game DLL). Bytecode is produced at map-load time by an in-binary compiler (bison parser, `yyparse` 0x08085932) from `.gsc` text read through the filesystem (`maps/mp/gametypes/<g_gametype>.gsc`, `maps/mp/<mapname>.gsc`, `codescripts/*.gsc`, `maps/mp/gametypes/_callbacksetup.gsc`, include files). The VM never sees source.

Layers, bottom to top [O unless tagged]:

1. **MT block allocator** (`MT_*`, 0x08076d26..0x08077154): power-of-two buddy allocator over a 64K-unit handle space (8-byte units, 512 KiB) at 0x08206f80, orders 0..16, free sets kept in the `Mem_BucketTree_*` structures of chunk 012. Used for strings, vector blocks and saved-stack buffers. Allocation failure -> `Scr_ErrorAndDisable("failed memory allocation for script usage")`.
2. **String pool** (`ScrStr_*`, 0x08078ec8..0x08079e74; `SL_*` in lineage): 16-bit handles, 8-byte header+inline text, hash table of 0x4000 four-byte nodes at 0x08287400. Reference counted. A string id is the only way a string travels through the VM (`VAR_STRING`).
3. **Variable table** (`ScrVar_*`, 0x0807a8ee..0x0807ce8c, plus `Scr_*` helpers in chunk 015): one global pool of 0xfffe sixteen-byte entries at 0x08297500. Every composite thing in script lives here: local-variable frames of threads, `level`, `game`, `anim`, structs, arrays, entity objects, waiting-thread registrations, time buckets, saved stacks. Children are found by hash `(name + parent) % 0xfffd + 1`.
4. **VM core** (`VM_ExecuteInternal` 0x08080158, 9340 bytes; 0x87 opcodes 0x00..0x86): value stack of 2048 `VariableValue` (8 bytes), local-variable id stack, 32-slot call-frame array, `setjmp`/`longjmp` error recovery.
5. **Call engine and builtin API** (`Scr_CallFunction` 0x08083e34 etc., `Scr_Get*`/`Scr_Add*` 0x08084694..0x0808529c): how C starts script threads, delivers notifies, and how builtins read arguments and push return values.
6. **Dispatch tables** in the game module (0x08188040 functions, 0x08188720 entity methods, 0x08158a40 player methods, 0x0815e3a0 mover methods, 0x0815a180 hudelem methods; field tables 0x0815e820 / 0x08157ce0 / 0x08159ee0). The compiler resolves a call to a handler pointer and stores it in a runtime-built table (`scrBuiltinTable`, 0x08205cb8, 1024 slots; `Scr_FindOrAddFuncTableEntry` 0x080704c6, string `SCR_FUNC_TABLE_SIZE exceeded`); the opcode operand is the 16-bit index into that table.
7. **Game glue** (chunks 046/048/050/051/052/103): callbacks (`CodeCallback_*`), notifies, entity/hudelem/player script fields, spawn of `script_struct`/`script_model`/`script_origin`.

Scheduling model [O]: single-threaded, cooperative. A script thread is a "local variable object" (type 0x0f..0x12) plus, while suspended, a heap block with its value-stack slice. `wait` converts seconds to ticks at a fixed 20 per second and files the suspended thread under `time array[tick]`. `G_RunFrame` (0x0810a13a) runs the bucket for the current tick through `Scr_ClearCurrentThread` (0x0808561a) and then increments the tick in `0x080855e2`, once per game frame. Script time therefore advances one tick per `G_RunFrame` call and `wait 0.05` = one frame only if the server runs at 20 Hz [I: `sv_fps` default is 20; I did not check how `G_RunFrame` is called relative to `sv_fps`].

### 2.2 Per frame [O]

`G_RunFrame` 0x0810a13a: advance level time, run the entity pair/touch queue (which uses `Scr_NotifyEntity`), `G_StopEntityScripts` 0x08109f14 (runs `Scr_ClearCurrentThread` while an entity think step reports work), then `0x080855e2`: `Scr_ClearCurrentThread()` (call 0x080842a4), `Scr_FlushEntityReleaseChain()`, `scrVarPub_time = (scrVarPub_time + 1) & 0xffffff`.

`Scr_ClearThreadEntry` 0x080842a4 (the function behind `Scr_ClearCurrentThread`): `if (timeArrayId) { entry = find(timeArray, scrVarPub_time); if (entry) { Scr_ShutdownThreads(value(entry)); remove(timeArray, time); } }`. `Scr_ShutdownThreads` 0x08083d12 pops each child of that bucket in insertion order, `Scr_RestoreVarList` rebuilds its stack slice, and calls `VM_ExecuteInternal(...)`. Because notified threads are appended to the current-time bucket (section 2.4), a thread woken by `notify` runs in the same bucket drain, after threads already queued. [I for the drain-order consequence; O for the code that appends to `time array[scrVarPub_time]`.]

### 2.3 C -> script [O]

* `Scr_CallScriptOffset(codeOffset, argc)` 0x08083fd6: offset is relative to the code base `0x08397548`; allocates a thread on `level` (`AddRef(levelId); AllocThread(levelId)`), runs `Scr_CallFunction`, pops the return value, returns the thread id (16 bit). Callers release it with `Scr_ReleaseHandle` 0x080841d6.
* `Scr_CallMethod(entnum, classnum, codeOffset, argc)` 0x08084062: same with `self` = `Scr_GetOrCreateClassEntityVar(entnum, classnum)`. `Scr_CallEntityMethod(ent,off,argc)` 0x0811b284 passes `(ent->number, 0)`.
* `Scr_SpawnThread` 0x080840f4 / `Scr_SpawnMethodThread` 0x0808415c: as above but release the thread and leave the return value as parameter 0 of the calling builtin (used by `G_SpawnScriptStructFromSpawnVars` 0x0811a828, which then reads `Scr_GetObject(0)`).
* `Scr_CallFunction(thread, codepos, argc)` 0x08083e34 (parameters are misnamed in the chunk, see section 10): `Scr_ClearInParams`, nests at most 0x1e frame cells (`scr_call_depth < 0x1e`), temporarily overwrites the type of the slot just below the first argument with the marker type 8 (`VAR_PRECODEPOS`; saved and restored), runs `VM_ExecuteInternal(codepos, thread, 0, top, base)`, restores. On overflow: `ScrVar_RemoveThread`, releases the arguments, `ScrRuntime_Error(..., "script stack overflow (too many embedded function calls)")`.
* Callbacks used by the game [O: assignments in `GScr_LoadGametypeScript`, call sites by `dis.txt` xref]: `ClientConnect` 0x080f8e7a -> `G_CallEntityScriptA` 0x08118350 (offset 0x0884d710, PlayerConnect); `ClientDisconnect` 0x080f94ce -> `G_CallEntityScriptB` 0x08118384 (0x0884d714); `G_DamageClient` 0x08101b40 -> `G_CallPlayerDamageCallback` 0x081183b8 (10 args, offset 0x0884d718); `player_die` 0x0810175a -> `G_CallPlayerKilledCallback` 0x08118492 (9 args, 0x0884d71c). Argument order is pushed last-to-first; `Scr_AddIndex` pushes plain ints.
* Notifies from C: `Scr_NotifyEntity(ent, stringId, argc)` 0x0811b2de -> `Scr_RunNestedCall(entnum, classnum=0, stringId, argc)` 0x08083a6e -> `Scr_RunVarListCalls(objectId, stringId, args)` 0x0808359e. Examples: `Cmd_CallVote_f` 0x080ffbb2 notifies string 0x0885329e (`"call_vote"`) with 3 string args (`Scr_NotifyEntity3Strings` 0x08118562); `Cmd_Vote_f` 0x08100960 notifies 0x088532a0 (`"vote"`) with 1 string (0x081185aa).

### 2.4 Inside the VM [O]

* Thread creation by an inline call (`OP_ScriptFunctionCall*`, `OP_ScriptThreadCall*`) never recurses on the C stack except for builtin-initiated calls: `VM_ExecuteInternal` keeps a local `nestedCalls` counter and a `callMarker` in `function_frame`, and re-enters its own dispatch (`call_enter`/`thread_return`). Embedded call depth is limited by the 32-cell `function_frame_start` array (`SCR_VM_MAX_FRAMES`) and the check `scr_call_depth < 0x1e` in `Scr_CallFunction`. The message for exceeding it is `script stack overflow (too many embedded function calls)`.
* `OP_wait` (0x4c): operand float or int; `ticks = round(sec * 20)` (a non-zero request that rounds to 0 becomes 1); int -> `sec*20`; `ticks > 0xfffffe` -> `wait is too long`; negative -> `negative wait is not allowed` (the code falls into `OP_waittillFrameEnd`'s tail after raising, as `Scr_Error` normally longjmps). Then `Scr_BuildVarList` (saves the stack slice: values from the thread's start slot to top, plus the local ids and nested call frames, section 4.6), `timeArray[(ticks + scrVarPub_time) & 0xffffff]` gets a child keyed by thread id holding the `VAR_STACK` handle, and the thread's variable type becomes 0x11 (time thread, wake tick in the name bits). `Scr_SampleTimers` (0x08085628: `0x083dce98 = rdtsc>>16`, `0x083dce9c = Sys_Milliseconds()`) is called when ticks != 0, resetting the infinite-loop watchdog.
* `OP_waittillFrameEnd` (0x4d): same but filed under `timeArray[scrVarPub_time]` with `ScrVar_NewChildBVarIdBias` (opposite end of the bucket ring than `NewChildA`).
* `OP_waittill77/78` (0x77, 0x78): `top` = object id, `top[-1]` = string id (errors `first parameter of waittill must evaluate to a string`, `%s is not an object`). Registers `object[0x1fffe][stringId][threadLocalId] = VAR_STACK`, and a reverse registration `0x08397520[self][threadLocalId] = object` so that thread termination can unhook it (`ScrVar_RemoveThread` 0x0807b8ae). Thread type becomes 0x10 (notify thread, string id in name bits). **chunk_016.cpp uses key `0x20000` for the per-object notify list; the instruction stream at 0x08081b2c and 0x08081d36 pushes `0x1fffe`.** Treat the chunk constant as a transcription error (section 10).
* 0x77 vs 0x78 [I, from the notify side]: `Scr_RunVarListCalls` tests `hdr[-1] == 'w'` (0x77), then reads `hdr[0]` as a parameter count and compares the stored values with the notify arguments using `Scr_EvalEquals` (error reported through `ScrRuntime_Error`); only on a full match is the thread woken, with `owner + 1` skipping the count byte. That is `waittillmatch` behaviour, so opcode 0x77 = waittillmatch and 0x78 = waittill. Both share one VM handler because the count byte is consumed on resume, not at suspend. [O: the 'w' test; I: the opcode names.]
* `OP_notify` (0x79): requires `top` = object id (type < 0x16) and `top[-1]` string id -> `Scr_RunVarListCalls(object, string, args)`; releases both and the argument slice down to the `VAR_PRECODEPOS` marker. `OP_endon` (0x7a): `AllocThread(localId)` as an "endon" thread (type 0x10), registers it under `object[0x1fffe][string]` and the reverse table; string id stays in the thread's name bits.
* Notify delivery (`Scr_RunVarListCalls` 0x0808359e): `list = object[0x1fffe]`; `waiters = list[stringId]`; iterate waiters with `Scr_GetSiblingViaPrevLinks`; for a registration with no stored value (type 0, which is what `OP_endon` leaves): unlink it, drop the reference it holds on the waiting thread (`ScrVar_ReleaseAuxOnly`) and do not schedule it; how the waiting thread is then terminated is [U]; for a waittill thread: optionally match arguments, append saved arguments to the stack buffer (reallocating via `MT_SizeOrderLE`/`StrPool_AllocBlock` if it no longer fits), file the thread under `timeArray[scrVarPub_time]`, `ScrVar_SetTimeThread(thread, scrVarPub_time)`. `scr_compile_error_deferred` (0x0839750c) is set to 1 during delivery [O]; role [U].
* `OP_jumpback` (0x63) watchdog: if `Sys_Milliseconds() - scrVmGlob_starttime < 0x9c4` (2500 ms) continue; else if `scrVmGlob_loading` print `script runtime warning: potential infinite loop in script.` plus location, reset timer and continue; else if `scrVmPub.abort_on_error` raise `Scr_ErrorAndDisable("potential infinite loop in script")`; else print `... killing thread.` and unwind the thread (and its embedded callers) with `ScrVar_RemoveThread`.
* Error path: `Scr_Error(msg)` (0x080853fc) sets `scrVarPub_error_message`, calls `Scr_ErrorInternal` 0x08080050: if `evaluate == 0 && developer_statement == 0` then (`developer && loading` -> terminal_error = 1) and `if (function_count != 0 || debugCode != 0) longjmp(g_script_error[g_script_error_level], -1)`; otherwise (and when terminal) `Com_Error(1, "%s", message)`. The `setjmp` target in `VM_ExecuteInternal` runs a per-opcode repair block (`error_recovery`), adjusts `scrVarPub_error_index` for the failing parameter, releases operands, reports with `ScrRuntime_Error` 0x080788d2 and kills the thread. `ScrRuntime_Error` is silent when `developer == 0 && terminal_error == 0` [O: first test of the function]; with developer on it prints `******* script runtime error *******`, the `called from:` / `started from:` frames from `function_frame_start`, then `Com_Error(4 or 5, "script runtime error\n(see console for details)...")` when recoverable/terminal flags require it. Exact `Com_Error` code semantics 4/5/6 are [U] (they differ from the 1 used for compile errors).

### 2.5 Builtin ABI [O]

* Handlers are `void (*)(void)` (functions), `void (*)(uint32 entref)` (methods). `OP_CallBuiltin*` sets `scrVmPub.top = top` (functions) or `top - 1` (methods; `top` then holds the object), `scrVmPub.inparamcount = n`, reads the 16-bit table index, stores the resume `pos` in the current frame, calls the handler, then releases any unread input parameters (`inparamcount` values), and if the handler pushed no result (`outparamcount == 0`) pushes `undefined`. Parameter `i` is `scrVmPub.top[-i]` (arguments are pushed in reverse source order, so parameter 0 is the first source argument). `Scr_Get*` check `param < inparamcount` else `parameter %d does not exist`, and the type, else `type %s is not an int` etc. through `scrVarPub_error_index = param + 1`.
* `Scr_Add*` (0x08085140..0x08085338) call `Scr_ReserveStackSlot` 0x08083df8 (`Scr_ClearInParams`, overflow -> `Com_Error(1, "Internal script stack overflow")`, then `top++`, `outparamcount++`) and write the slot (pre-increment push: the new slot is `top[0]` after the increment).
* Method entry: `entref = (classnum << 16) | index` as returned by `Scr_GetVarInfoPair` (aux = index in the low half, `info >> 8` = classnum in the high half). The VM refuses non-entity objects (`%s is not an entity`, requires variable type 0x15). `Scr_GetEntity` returns the pair; `Scr_GetEntityParam` 0x0811b16e rejects `ref >> 16 != 0` (`not an entity`); `HudElem_FromHandle` 0x08103e18 requires `handle >> 16 == 1` (`not a hud element`).
* Method lookup (`Scr_GetMethod` 0x08117dea): player (59, table 0x08158a40), mover (12, 0x0815e3a0), entity (59, 0x08188720), hudelem (18, 0x0815a180); all four searches always run; the first non-null handler wins; each successful search overwrites `*name` with the table's canonical string pointer, and `*developer` is set from the entity table only (initialised to 0). Function lookup (`Scr_GetFunction_08117cb2`): 145 entries of 0x08188040, case-sensitive `strcmp`.

## 4. Data formats

### 4.1 Variable table entry (0x10 bytes) [O]

```
+0x00 u16 var      hash-slot view: id of the variable stored in this slot
+0x02 u16 link2    slot back-link / free-list prev
+0x04 u32 value    union: payload (object id, int, float bits, string id, vector ptr) or {u16 refCount, u16 aux}
+0x08 u32 info     bits 0-4 type, bits 5-6 status (0x00 free-in-chain, 0x20 chained, 0x40 bucket head, 0x60 unused/value), bits 8-31 name key
+0x0c u16 link12   slot ring link
+0x0e u16 link14   child ring link
```
An index is used as both a *slot* and a *variable*. `var` selects the variable that currently lives in the slot; `info` and `u` belong to the variable. Collision handling is coalesced chaining with relocation (`ScrVar_AllocateInSlot` 0x0807ab64 moves entries when the home slot is occupied by a variable that does not hash there). Lookup `ScrVar_FindVariable(parent, name)` 0x0807ab22: `slot = (name + parent) % 0xfffd + 1`, bucket head must have status 0x40, then walk the `link12` ring comparing `info >> 8`. Free list: entry 0's `u.s.refCount` is the head, entries chained through `refCount` (next) and `link2` (prev). Exhaustion -> `Scr_ErrorAndDisable("exceeded maximum number of script variables")`. Children of an object form a ring through `link14` with the object itself as head; `Scr_GetNextSibling(id)` = `g_scrVar[g_scrVar[id].link14].var`, and returns 0 when that variable's type is > 0x0e (reached the owner, whose type is >= 0x0f).

Chunk 015 names the same fields `link_a (+0)`, `link_b (+2)`, `pad_0c (+0xc, "not accessed")`, `link_slot (+0xe)`. They are the same bytes; chunk 014's names are the ones with consistent code (see `script-vm.structs.json`).

### 4.2 Value types [O]

Value types on the stack (`VariableValue.type`), from the string table 0x0817d960 and OP handlers: 0 undefined, 1 object (pointer to a variable id), 2 string, 3 localized string, 4 vector, 5 float, 6 int, 7 codepos (frame bottom marker), 8 precodepos (call/parameter start marker), 9 function, 10 stack (saved stack buffer), 11 animation (packed `index | tree << 16`). Variable types (low 5 bits of `info`) continue: 12 developer codepos, 13 include codepos, 14 "thread list", 15 thread, 16 notify thread, 17 time thread, 18 child thread, 19 struct ("struct" name; used for `level`/structs/`script_struct`), 20 removed entity, 21 entity, 22 array, 23 removed thread. Names 15..18 all print as `thread`. Types 16/17 keep the string id / wake tick in `info >> 8`; type 18 keeps the parent thread's local id there (`ScrVar_GetChildThreadParent` 0x0807b840).

Chunk 015's enum calls 0x13 and 0x14 `ENTITY_A/B` with the comment `"thread"/"struct" name slots`; 0x13 is struct and 0x14 is removed entity [O from `ScrVar_AllocStruct` 0x0807bbf0 and `ScrVar_Release` 0x0807be2c].

### 4.3 Name key space [O]

The 24-bit key in `info >> 8` of a child names it. From `ScrVar_NameToValue` 0x0807c57c and the `*24`/`*Bias` wrappers (0x0807c104..0x0807c1f6):

| Key | Meaning |
|---|---|
| `< 0x10000` | string id (field/variable name) or field-name slot index (see open question 4) |
| `0x10000 + id` (`...Bias` helpers), up to `0x1fffd` | an object/variable id (thread local ids, entity pointers, array of objects) |
| `0x1fffe`, `0x1ffff` | reserved: `0x1fffe` = notify registry of an object, `0x1ffff` = saved-stack registry; hidden by `ScrVar_EnumerateNames` 0x0807c35e |
| `>= 0x1fffe` up to `0xfdffff` | integers: `(x + 0x800000) & 0xffffff` (`Scr_BiasName24`); `Scr_IsSmallNameIndex` accepts `x + 0x7e0002 < 0xfe0002` |

Array indices (integers) therefore use the `...24` helpers, string-keyed fields the plain ones, object-keyed registrations the `...Bias` ones. The time array uses plain keys (the tick, <= 0xffffff; `ScrVar_GetNewVarValueId(timeArray, ticks)`), so tick keys below 0x10000 share the string namespace of a different parent - harmless because the parent differs (hash includes the parent id).

Entity release chain: `Scr_QueueEntityRelease(index, classnum)` 0x0807e5e0 re-tags the entity's variable as 0x14, removes it from `entArray`, links it into `0x08397530` through its `u.s.aux` (`arr.size`) and `AddRef`s it. `Scr_FlushEntityReleaseChain` 0x0807e69a (also called at the end of `G_InitGame` and by `0x080855e2`) pops each, runs `Scr_ClearObjectChains` (kills waiters on that object), frees children, releases. `G_FreeScriptEntity` 0x0811b128 and `G_FreeClassObject1` 0x0811b1ca (hudelem, class 1) call it.

### 4.4 Entity objects and class field tables [O]

An entity is a type-0x15 variable whose `info >> 8` is the class number and `aux` its index; one per live gentity/hudelem is created on demand by `Scr_GetOrCreateClassEntityVar(index, classnum)` 0x0807e9f8 inside `g_scrVar[g_scrClassInfo[classnum].entArrayId]` (key `Bias24(index)`). Script field access on an entity first looks for a plain child; if absent, the class field map (`fieldMapId`, registered by `Scr_AddClassField` 0x0807e846 under two keys: `Bias24(slot)` and the raw string id) gives a 16-bit field index which is dispatched to C: class 0 -> `Scr_SetEntityField` 0x0811acb2 / `Scr_GetEntityField` 0x0811aeb2; class 1 -> hudelem handlers. Entity field indices with both top bits set (0xc000) address the player field table (`Scr_RegisterPlayerFields` 0x080f84be registers each as `0xc000 | index`; `gentity+0x158` is the `gclient_s*`; chunk 051 names this member `clientData` and calls it a "class-1 script object": it is the client structure).

Field table types (`entityFieldDef`, 0x0815e820, 10 entries): 0 int, 1 float, 2 inline string, 3 script string id (u16), 4 vec3, 5 entity pointer, 6 "yaw" (vec3 (0, v, 0)), 7 u16 object handle, 8 model-name byte. Entries: classname +0x168 (type 3, read-only setter 0x0811a4dc), origin +0x138 (4, setter 0x08117e62), model +0x164 (8, read-only), spawnflags +0x170 (0, read-only), target +0x16a, targetname +0x16c (3), count +0x1a0, health +0x194 (setter 0x08117ed4), dmg +0x19c, angles +0x144 (4, setter 0x08117ea6). Radiant field files (`radiant/*.txt`, loaded by `Scr_AddFieldsFromFile` 0x0807f840; tokens `float|int|string|vector <name>`, names lowercased, errors `unknown type '%s' in '%s'`, `missing field name in '%s'`, `duplicate key '%s' in '%s'`, `cannot find '%s'`) extend spawn-string keys; `G_ParseScrFieldValue` converts them.

Player field table (0x08157ce0, 13 entries, `{name, offset, type, setter, getter}`, 0x14 bytes): name +0x2784 (string; setter 0x080f7d90 = read-only handler), sessionteam, sessionstate (custom get/set), maxhealth +0x2728, score +0x26b8 (custom setters), deaths +0x26bc (generic int, no custom handler), statusicon, headicon, headiconteam (custom), spectatorclient +0x26ac, archivetime +0x26b4, psoffsettime +0x27a4 (custom), pers +0x26c0 (type 7, read-only handler 0x080f7d90). Hudelem field table (0x08159ee0, 15 entries, stride 0x1c): x,y,z,fontscale,font,alignx,aligny,horzalign,vertalign,color,alpha,label,sort,foreground,archived; the `+0x14` slot is the **setter** and `+0x18` the **getter** (see section 10: chunk 048 has them swapped).

### 4.5 `scrVmPub` and frames [O]

```
+0x00 u32* localVars      +0x04 maxstack   +0x08 function_count   +0x0c function_frame (pointer)
+0x10 top                 +0x14 u8 debugCode  +0x15 u8 abort_on_error  +0x16 u8 terminal_error
+0x18 outparamcount       +0x1c inparamcount  +0x20 function_frame_start[32] (0x18 each)
```
Frame cell: `+0 pos` (resume code pointer; also what `ScrRuntime_Error` prints), `+4 localId` (thread local-variable object; 0 means "no thread, started from C" in the trace printer), `+8 localVarCount`, `+0xc callMarker`, `+0x10 callerStartTop`, `+0x14 callMarkerType`. Chunk 013 (`scr_call_entry_s` {pc, flags, ...}) and chunk 017 (`cod2_scr_frame_s`, `cod2_scr_thread_s` {owner, id, count}) are views of the same 0x083d8aa0 array. `localVars` is a stack of `u32` variable ids (one per local), `OP_CreateLocalVariable` pre-increments it; thread suspend/resume (`Scr_BuildVarList`, `Scr_RestoreVarList`, `Scr_PushChainIds`) saves and restores those ids. `scr_call_depth` of chunks 013/017 is `function_count` (0x083d8a88).

### 4.6 Saved stack buffer ("varlist") [O]

Packed, allocated with `StrPool_AllocBlock(11 + 5*count)`: `u32 owner` (resume code pointer; `owner[-1]` is the suspending opcode byte, `owner[0]` the waittillmatch count), `u16 count`, `u16 size`, `u16 head` (local id chain head), `u8 tag` (`scrVarPub_time & 0xff`, to tell whether the buffer outlived a frame: `Scr_RestoreVarList` calls `Scr_SampleTimers` when stale), then `count` records `{u8 type; u32 value}`. Type 7 records (`VAR_CODEPOS`) are call frames and are replayed into `function_frame_start` on restore. Chunk 015's `ScrFrameHeader`/`ScrFrameRecord` (used by `Scr_GetFrameWeight`) are the same layout (`recordCount@4`, `varId@8`, `records@0xb`).

### 4.7 Strings and vectors [O]

String record (8-byte unit at `str_pool + handle*8`): `u8 length` (text length+1 for C strings, 0 for long ones), `u8 flags`, `u16 refcount`, inline text from +4; longer strings continue into following units (`ScrStr_FindNulIndex` scans in 256-byte steps from `length-1`). `ScrStr_Hash` = polynomial `h = h*31 + c` over the text (`len >> 2` for 256+ bytes) `% 0x3fff + 1`. Hash node `{u16 link, u16 handle}` (link bits 14-15: state 0x8000 head-in-use, 0x4000 chained). Limits: `exceeded maximum number of script strings`, `max string length exceeded: "%s"`, string concatenation (`Scr_EvalPlus` 0x0807df3a) refuses `len(a) > 0x2000`. `ScrStr_*` flag byte bit 0x04 = permanent.

Vector value: pointer to 3 floats. Heap vectors come from `Scr_AllocVectorBlock` 0x0807bf86 (16-byte MT block, `u16 refcount` at block+0, byte at block+3 == 0 marks "heap", floats at block+4); `Scr_VectorAddRef/Release` only act when `vec[-1] == 0`, so bytecode-embedded constants (`OP_GetVector` points into the code) are never freed.

### 4.8 Debug/source tables [O]

`scr_file_table` (0x14-byte entries {key, first_line, line_count, ...}), `scr_line_table` (8-byte {value, flags}), `scr_frame_table` (0x18 {id, name, source, source_len, current_line, is_debug}), `scr_saved_src` (8 {text, length}); `ScrDbg_*` 0x080771dc..0x080785ac. Without developer mode `ScrDbg_PrintLocation` prints `@ <offset from code base>` (strings `@ %d`, `<frozen thread>`, `<removed thread>`), with it `(file '%s'%s, line %d)`. These tables are only populated when `scr_debug_enabled` (= `scrVarPub.developer`, set from the dvars described above).

### 4.9 Builtin table entries [O]

`{const char *name; void *handler; int developerOnly}` (12 bytes). Function table 145 entries, `developerOnly = 1` for print, println, print3d, line, assert, assertex, assertmsg, getentbynum. Entity methods 59, player 59, mover 12, hudelem 18 (hudelem entry third word unused by lookup).

## 8. Behaviours a native port must reproduce

1. Variable pool: ids are 16 bit (`Scr_GetPointer`/object handles, `Scr_AddObject(uint16 id)`), the hash `(name+parent) % 0xfffd + 1` only affects performance, but the **limit of 0xfffd (65533) live variables and the fatal `exceeded maximum number of script variables`** are observable. A port may use a different container if it keeps the limit, ids 1..0xfffd, the reserved pseudo id 0xfffe and the shared-array rules. [I: only stress scripts hit the limit.]
2. Reference counting of strings, vectors, objects with the exact release points in the VM; entity objects are retagged and queued rather than freed immediately (section 4.3), so `waittill`/`endon` on a freed entity are resolved at end of frame, not at `delete`.
3. Time model: 20 ticks per second, `wait` rounding, `waittillFrameEnd` ordering (opposite end of the bucket ring), notify wakeups appended to the current tick bucket. Waiting threads of one bucket run in insertion order. 24-bit tick wrap.
4. Notify semantics: an `endon` registration is consumed by a `notify` of the string on the same object (the owning thread is terminated by a mechanism not fully traced, section 11 item 8); `waittill` threads are queued with the notify arguments appended to their saved stack; `waittillmatch` (opcode 0x77) compares with `==` semantics (`Scr_EvalEquals`) and ignores non-matching notifies without consuming.
5. Argument conventions: parameter index = distance from `top`, arguments pushed in reverse; `undefined` pushed when a builtin returns nothing; unread arguments are released after the call; error positions are `param + 1` with the repair rules in `error_recovery`.
6. Callbacks: argument order and counts in section 2.3, `CodeCallback_*` resolution at map load with `Could not find script '%s'` / `Could not find label '%s' in script '%s'` fatal errors (`Com_Error(1)`), missing level script is not an error.
7. Operators (`Scr_Eval*` 0x0807d1fa..0x0807e3b4): `pair '%s' and '%s' has unmatching types '%s' and '%s'` after numeric/string casts (`Scr_CastNumericPair`, `Scr_CastStringPair`), `divide by 0`, `cannot cast %s to bool` / `to string`, `~ cannot be applied to "%s"`, `size cannot be applied to %s`, string concat limit 0x2000, `Scr_ConvertToDisplayString` formats floats as `%g` and vectors as `(%g, %g, %g)`.
8. Arrays/strings/vectors indexing errors (`array index %d out of range`, `string index %d out of range`, `vector index %d out of range`, `read-only array cannot be changed`, `string characters cannot be individually changed`, `vector components cannot be individually changed`, `%s is not an array, string, or vector`). Arrays are shared copy-on-write: for an array object `u.s.refCount` counts extra sharers, and a write through `Scr_GetArrayForWrite` 0x0807eea8 copies it first when `refCount != 0` (`ScrVar_CopyChildren`). An array coming from an entity field class getter with `refCount == 0` is C-owned and writing it raises `read-only array cannot be changed`. [O]
9. `ScrVar_ReadClassField` returns a copy of shared arrays read from entity fields (so scripts cannot mutate C-owned arrays).
10. Runtime error reporting: silent without `developer`, trace with it, `Com_Error` codes/`ERR_*` mapping to be copied from the engine lane; `scriptUsage` output format.
11. Loop watchdog: 2500 ms wall clock since the last `Scr_SampleTimers`; warning-only while `loading` is set; thread kill otherwise (or terminal error when `abort_on_error`, i.e. `developer` nonzero).
12. Embedded call depth: error text `script stack overflow (too many embedded function calls)`; value stack overflow `Internal script stack overflow` (C side) and `VALUE_STACK_SIZE exceeded` / `LOCAL_VAR_STACK_SIZE exceeded` (compiler side).
13. `Scr_ClearThreadEntry`'s drain loop must tolerate buckets being appended to while drained (notify inside a thread being run).
14. Field dispatch: plain child first, then class field map, then `0xfffe` pending field for entity writes; field type table semantics in section 4.4 (including the `0xc000` player prefix).
15. Print gating by `g_no_script_spam`; `print` of each argument via `%s` after `Scr_GetString` casting.

## 10. Naming problems found (with evidence)
