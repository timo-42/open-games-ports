## 1. Purpose and architecture as implemented in this binary

The common core is the Quake-III-style "qcommon" layer of a **single-threaded, dedicated-only** server process:

* A C `main` (Sys_Main) does Linux setup, calls `Com_Init(cmdline)` once, then loops forever: `usleep(5000); Com_Frame();` plus per-iteration PunkBuster hooks. [O] (objdump 0x080d4f7c..0x080d5118)
* `Com_Frame` is wrapped in `setjmp`; every error (`Com_Error`) `longjmp`s back to it, after which `Com_ErrorRecover` resets state (section 5). [O]
* All state that survives frames lives in global variables (no heap-allocated "context"). There is **no zone allocator**: `Com_Malloc*`/`CopyString` are thin libc `malloc/calloc/free` wrappers, and the only structured memory is a calloc'ed **hunk** with high/low ends plus a small bump "pool" for temporaries. [O]
* "dedicated" is hard-registered ROM `2` (`Com_InitDvars`), so every client-only branch (`com_maxfps`, intro cinematics, viewlog console) is dead on this binary but still present in the code. [O] (0x08061d90)
* Threads: six recursive pthread mutexes and per-thread "value" slots exist, but `pthread_create` is not imported (libpthread imports are only `pthread_mutexattr_init/settype/destroy`, `pthread_mutex_init/lock/unlock`, `pthread_self`). Thread slot index 0 is the only one ever populated. [O] imports; [I] single-threaded in practice.
* Dvars (the CoD2 name for cvars) are a fixed pool of 0x500 records with a case-insensitive name hash, a name-sorted singly linked list, typed value words, latch/reset/cheat/read-only/write-protect semantics and a "user-created string dvar that is later retyped on registration" mechanism.
* Commands: one text buffer (64 KiB), a move-to-front singly linked command list, Q3-style tokenizer, plus fallthrough: command not found -> dvar command -> PunkBuster `pb_sv_` -> game `G_ConsoleCommand`.

### 2.4 Event loop (all [O] from chunk_006/038 plus disassembly of the ring indices)

* Two 256-entry rings of `sysEvent_t` (0x18 bytes): the **system** ring `eventQue` @0x085e5060 (head 0x085e6860, tail 0x085e6864; `Sys_QueEvent` 0x080d47a2, warns `Sys_QueEvent: overflow` and frees the overwritten payload) and the **pushed** ring `com_pushedEvents` @0x081a3300 (head 0x081a3280, tail 0x081a3284; `Com_PushEvent` 0x08061670, warns `WARNING: Com_PushEvent overflow`).
* `Sys_GetEvent` (0x080d484e): pop eventQue; else poll `Sys_ConsoleInput` -> queue type 4 (console text, heap copy), poll one UDP packet via `Sys_GetPacket` (into the static 0x20000-byte buffer at 0x085e6880) -> queue type 5 whose payload is `netadr(0x14 bytes) + packet bytes`; return the next event or a zeroed event stamped with `Sys_Milliseconds()` (type 0 = empty = "end of poll"). At most one console line and one packet are polled per call.
* `Com_GetEvent` (0x0806179c): pushed ring first, else `Sys_GetEvent`.
* `Com_EventLoop` (0x0806182a): temporary 0x20000-byte message buffer taken from the pool (`Com_PoolAllocInto2` ... scoped `Com_PoolRestoreFrom2`); type 0: drain loopback packets for socket 1 (`NET_PollLoopPacket(1,...)` -> `SV_ReadPackets` only if `sv_running`), return the event time; type 4: `Cbuf_AddText(text); Cbuf_AddText("\n")`; type 5: copy netadr, bound check `cursize <= maxsize` else `Com_EventLoop: oversize packet`, deliver to `SV_ReadPackets_080960e2` only while `sv_running`; other: `Com_Error(0, "\025Com_EventLoop: bad event type %i")`.
* `Com_PumpSysEvents` (0x08061b7c) pulls events from `Sys_GetEvent` into the pushed ring until an empty event and returns its time; it is the engine's millisecond clock used outside the frame (Com_Init seeds, `freeze`). `Com_ProcessConsoleEvents` (0x08061ab8) is a network-less drain (no direct callers found by objdump: dead or called indirectly) [O/U].

## 3. Command buffer and command system (chunk_006, [O] unless noted)

Globals: `g_cmd_text` ptr 0x0817d77c -> `cmd_text_s g_cmd_text_buffers[1]` 0x0818f084 (stride 0xc), storage 0x0818f100 (0x10000 bytes), `g_cmd_wait` 0x0818f080; `cmd_argc` 0x0819f100, `cmd_argv[0x200]` 0x0819f180, `cmd_tokenized[0x2200]` 0x0819f980, `cmd_functions` 0x081a1b80, `cmd_args[0x400]` 0x081a1c00.

* `Cbuf_Init` (0x0805fc9a) loops `for i<1`: **only one** command buffer exists (the Q3 `CBUF_*`-per-client-slot idea is absent). `Cbuf_AddText` (0x0805fd0a): prints `Cbuf_AddText: overflow\n` when `cursize+len >= maxsize` (strict: the buffer can never be completely filled). `Cbuf_InsertText` (0x0805fd82): shifts pending text up, copies `text` then `'\n'` (`Cbuf_InsertText overflowed\n`). `Cbuf_ExecuteText(when,text)` (0x0805fe3c): 0 = run now (`Cmd_ExecuteString(text)` or drain if empty), 1 = insert, 2 = append, else `Com_Error(0,"\025Cbuf_ExecuteText: bad exec_when")`.
* `Cbuf_Execute` (0x0805feb6): honours `g_cmd_wait` (decrement and return **before** executing; `wait` with no argument sets 1, `wait N` sets `atoi`); a line ends at `\n`, `\r`, or an unquoted `;`; the line is capped: if `i > 0xffe` then `i = 0xfff` (a 4095-byte line limit, with the remaining text re-parsed as the next line); text after the separator is `memmove`d down. This is a per-call loop with no re-entrancy guard (nested `exec` uses `Cbuf_InsertText`).
* `Cmd_TokenizeStringInternal` (0x08060346): up to **0x200 tokens**, returns 0 when full; whitespace is "any signed char < '!'" (so bytes >= 0x80 count as separators); `//` ends the line; `/* */` skipped; quoted tokens with `\"` escape; `limit` counts down per token and when it hits 0 the **rest of the line becomes one token** (limit 0 never triggers). The `_alt` copies of Cmd_Argc/Argv/ArgvBuffer/TokenizeString* are separate symbols with identical bodies on the same globals and **are called** (Cmd_Argc 35 direct callers vs Cmd_Argc_alt 22; Cmd_Argv 61 vs _alt 37) (objdump caller counts) - i.e. duplicated by the compiler/TU split, not dead.
* `Cmd_AddCommand` (0x080606b6): linear exact-name (case-**sensitive** `strcmp`) lookup; duplicate with non-null function prints `Cmd_AddCommand: %s already defined\n` and **keeps the old function**; a null function on an existing name is silent. Nodes are 0x14 bytes from `Com_MallocZeroed`; name via `CopyString`. `Cmd_ExecuteString` (0x080608a6) looks up **case-insensitively** (`Q_stricmp`) and **moves the hit to the list head** (so list order changes with use; `cmdlist` order is therefore history dependent). A matching node with a null function falls through. `Cmd_SetCommandAuxPair` (0x0806079c) stores path/extension words at +8/+0xc used by `Cmd_FileCompletion` (0x08060838, chunk_100) for tab completion; no null check on the lookup (crash on unknown name).
* Fallthrough after "no command matches" [O]: if the line starts with `pb_` (case-insensitive) and then `sv_` -> `PB_DispatchEvent3(0xe,-1,len+1,text)` (PunkBuster server command; other `pb_` lines are dropped silently); else `Dvar_Command()`; if that returns 0 and `sv_running` is set -> `SV_QueryGameActive()` (really `G_ConsoleCommand` gated on `sv.state == 2`; see naming section).
* Registered by `Cmd_Init` (0x08060a82): `cmdlist`, `exec`, `vstr`, `wait`. `exec` appends `.cfg` if no extension (`COM_DefaultExtension(name,0x40,".cfg")`), reads the file through `FS_ReadFile`, prints `execing %s\n`, then **inserts** the text (executes immediately after the current line). `vstr` accepts dvar types 6 (enum) and 7 (string) only.
* `Cmd_Shutdown` frees the list. `Cmd_PrintArgs_f` (0x08060196) is not registered by Cmd_Init (registered elsewhere, [U] where).

## 4. Dvars (chunks 028, 029, 007, 100)

### 4.1 Storage and lookup [O]
* Pool: `struct dvar_s g_085abe20[0x500]` (stride 0x24; 0x085abe20 + 0x500*0x24 = 0x085b7220 = the hash table address, a strong layout cross-check). `dvar_indexCount` @0x085abe08; limit message `Can't create dvar '%s': %i dvars already exist` raised with `Com_Error(0,...)` (fatal) when `count > 0x4ff`.
* Hash: 256 buckets `g_085b7220[0x100]` (0x400 bytes, memset at shutdown). `generateHashValue` (0x080b1274): `sum_i (i+0x77)*tolower(name[i])` `& 0xff`; null name -> `Com_Error(1,"\025null name in generateHashValue")`. `Dvar_FindHashed` (0x080b2e54): lock critical section 4, bucket walk with `Q_stricmp`, chain `hash_next` (+0x20); `Dvar_Lookup` (0x080b2ed8) wraps it.
* Sorted list: `dvar_vars` @0x085abe00; insertion keeps **ascending `strcasecmp` order, with equal names inserted after existing equals** (`>= 0` advances). Iteration order of `dvarlist`/`dvardump`/`Dvar_InfoString`/`seta` writing is therefore alphabetical case-insensitive. `dvar_modifiedFlags` @0x085abe04 collects `OR` of the flags of every dvar changed through `Dvar_SetVariant`; bit 0 (ARCHIVE) is what triggers `Com_WriteConfiguration`.
* Locking: all mutating/lookup paths take `Sys_EnterCriticalSection(4)` (mutex index 4, recursive). [O]
* Value words: `current`@+8, `latched`@+0xc, `reset`@+0x10, each 32 bits: inline for bool (low byte), float bits, int, enum index, packed RGBA bytes; pointer for strings; pointer into a heap block of `3*n` floats for vec2/3/4 (`Dvar_AllocValueBlock` allocates `type*12` bytes, current/latched/reset at `block + type*4*{0,1,2}`, i.e. `type` doubles as float count). `domain_min`@+0x14/`domain_max`@+0x18: min/max (int or float bits) or, for enum, `count` and `const char **names`.
* Type tags (byte +6) [O]: 0 bool, 1 float, 2 vec2, 3 vec3, 4 vec4, 5 int, 6 enum, 7 string, 8 colour (RGBA).
* Strings: `Dvar_CanonicalString` (0x080b142a) returns the shared literal for `""`, single digits (table 0x0814f3ec, 2-byte stride), `"off"`, `"on"`, otherwise `CopyString` (malloc). `Dvar_ReleaseValueString` frees only non-canonical strings; `Dvar_SetCurrent/Latched/ResetString` reuse an identical sibling word before allocating.

### 4.2 Flags (word +4) [O unless noted]
Bits verified by messages/legend in `Dvar_SetVariant`, `Dvar_List_f`, `Dvar_WriteVariables/Defaults`:
`0x0001` ARCHIVE (written as `seta`), `0x0002` USERINFO ("U"; `setu`), `0x0004` SERVERINFO ("S"; `sets`; `0x0404` also shown as S), `0x0008` SYSTEMINFO [I from `sv_cheats 0x1018`, lineage], `0x0010` write-protected ("I" in `dvarlist`; message `%s is write protected.`), `0x0020` LATCH ("L"), `0x0040` read-only ("R"; `%s is read only.`), `0x0080` CHEAT ("C"; `%s is cheat protected.`), `0x1000` **set by every in-code registration** (all 155 `Dvar_Register*` calls with a literal flag word in finished chunks include 0x1000) [O count]; role [I]: "registered by code, not user-created", `0x2000` [U] (part of the 0x7000 change mask), `0x4000` OWNS_NAME (name and string heap-owned; created by `Dvar_SetOrCreate*`/`Dvar_SetStringOrCreateEx`), `0x8000` [I] "value changed by user/config after startup" (set by `Dvar_SetFromUserInput` when the load gate is on), `0x0400` cleared by `Dvar_ClearUnknownFlag0400` (called from `SV_ClearMapTempState` 0x08093478; role [U]).
`Dvar_WriteDefaults` skips dvars with any of `0x40c0` set (= `0x4000` OWNS_NAME | `0x0080` CHEAT | `0x0040` ROM), and `cl_cdkey`; i.e. user-created, cheat and read-only dvars are never written as defaults. [O]

### 4.3 Register / create / update [O/I]
* `Dvar_Register*` (0x080b3f22..0x080b4300) = `Dvar_FindHashed`; miss -> `Dvar_Create` (0x080b3c48); hit -> `Dvar_Update` (0x080b3ab0). Typed wrappers (Bool/Int/Float/String/Enum/Color/Vec) only differ in the value word. `Dvar_Create` copies name only if flags contain 0x4000 (otherwise stores the `.rodata` pointer, so registration names must stay alive), allocates value blocks for vec types, canonicalises strings, inserts into sorted list and hash bucket.
* **Retyping of user-created dvars**: a command-line/console `set foo bar` for an unregistered name creates a **string dvar with OWNS_NAME** (`Dvar_SetStringOrCreateEx` 0x080b4fa2). When code later registers `foo`, `Dvar_Update` sees `(flags ^ d->flags) & 0x7000`, and `Dvar_ReplaceOwnedName` (0x080b38d8) -> `Dvar_ForceStringType` + `Dvar_Redefine` (0x080b3740): the existing text is **re-parsed against the new type/domain** (`Dvar_ParseValueWord`, `Dvar_ClampValue`, enum fallback to registration default), the registration value becomes the **reset** word, flags are OR-ed. This is how `+set net_port 28960` works before `NET_InitCvars`. Exception: if the new flags contain READ_ONLY, or CHEAT with `sv_cheats == 0`, the user text is discarded and the registration default is used. [O code; I intent]
* `Dvar_Update` tail: `flags |= new flags`; if CHEAT flag and `sv_cheats` is 0 -> `Dvar_SetVariant(reset, internal)` + `Dvar_SetLatched(reset)`; if LATCH -> `Dvar_ApplyLatched`.
* `Dvar_SetOrCreate{Bool,Int,Float,Vec2,Vec3,String,Color}` create a **string** dvar (value text printed with `%i`/`%g`) when absent; `Dvar_ClearFlagsGlobal` (0x080b352c) / `Dvar_ClearFlagsIfOwned` (0x080b34da) demote code-registered dvars back to user strings; **no direct callers found** (objdump) [O], so possibly dead or reached through pointers [U]. `Dvar_ResetAllCheatProtected` (0x080b50d0) also has no direct callers [O].

### 4.4 Setting semantics: `Dvar_SetVariant(d, value, source)` (0x080b2afa) [O]
Source codes: 0 internal, 1 user (console/cfg/rcon text), 2 "other" (user-like without the cheat test).
1. `Com_PrintMessage(4, "      dvar set %s %s\n")` - channel 4 is "log only" (never console, never redirect). **Every dvar set is logged** when `logfile` is on.
2. Domain check (`Dvar_ValueInDomain`): invalid -> `'%s' is not a valid value for dvar '%s'` + `Dvar_PrintDomain`; enum additionally resets to default; returns without setting.
3. Source 1/2 only: READ_ONLY -> message, return; WRITE_PROTECT -> message, return; source 1 + CHEAT + `sv_cheats==0` (no null check on the sv_cheats pointer) -> `%s is cheat protected.`; LATCH -> store into `latched`; if latched equals current do nothing, else print `%s will be changed upon restarting.` and return (current value unchanged).
4. If new value equals current: **writes the current value into `latched`** and returns (clears a stale latch). Else `dvar_modifiedFlags |= flags`, copy value to **both current and latched**, release old string, `modified = 1`.
Internal source (0) bypasses read-only, write-protect, cheat and latch (so code can always force a value; `Dvar_ApplyLatched` uses source 0).

## 9. Printing and logging [O]

`Com_Printf` 0x08060dea (vsnprintf 0x1000, forced NUL, channel 0) -> `Com_PrintMessage(channel, text)` 0x08060c20: calls `PB_ConsoleCapture(msg,0x1000)` first; **if no redirect**: skips a leading `^` + 1 char colour prefix (strips 2 chars), prints via `Sys_Print` unless `channel == 4`, then if `logfile != 0`: lock section 0; if the filesystem has search paths and no log is open, open `console_mp_server.log` (`FS_FOpenFileWriteText`), print `logfile opened on %s` (asctime) once; write the text; `FS_Flush` if `logfile > 1`. **If a redirect buffer is active** (`Com_BeginRedirect` 0x08060ba2: all three args non-null): channel 4 ignored; lock section 5; if `strlen(buf)+len >= size-1` flush through `rd_flush` and clear; `I_strncat` (rcon output; the `^` prefix is NOT stripped on this path). Note a log line is written for console text only and the "dvar set" lines (channel 4) never reach the console. `Com_DPrintf` 0x08060e3a only prints if `developer` is non-zero (but note `com_developer` global is dereferenced after a null check, so it is safe before `Com_InitDvars`).

## 11. Data formats and protocols the subsystem reads/writes

* Config files: plain text command lines, executed through the command buffer; written by `writeconfig` (`seta` lines of archived dvars from `latched` text, header `// generated by Call of Duty, do not modify`) and `writedefaults` (`set` lines). The autosave file is `config_mp_server.cfg`; read files: `<fs_defaultConfigName>`, `language.cfg`, `config_mp_server.cfg`, `safemode_mp_server.cfg`. [O]
* Command line: `argv[1..]` joined by spaces, split at `+` or `\n` into at most 32 console lines (`Com_ParseCommandLine` 0x0806129e: the `+` is overwritten with NUL; a `+` inside a quoted value or password would split it [O]); `safe` or `dvar_restart` lines set safe mode (blanked); only `set`/`seta` lines execute early. Others are `Cbuf_AddText`'ed in `Com_AddStartupCommands`.
* Log file `console_mp_server.log` (plain text, color codes stripped by the 2-char skip only when text starts with `^`).
* Event structures: `sysEvent_t` (0x18) with types 0 none, 4 console text, 5 packet (payload `netadr(0x14)+data`).
* Info strings: `\key\value\key\value`, limit 0x400 (small) / larger "Big".
* MD4: `MD4_Init/Update/Final/Transform` and `Com_BlockChecksum` 0x08067b02 / `Com_BlockChecksumKey` 0x08067b5e (net/fs hash helpers; not analysed here).

## 13. Behaviours a native port must reproduce (checklist)

1. **Single command buffer, 64 KiB, strict overflow rule, 4095-byte line cap**, `wait` semantics, `;`-splitting outside quotes, `exec` inserting the file content immediately (section 3). [O]
2. **Command lookup semantics**: add = case-sensitive duplicate check, execute = case-insensitive with move-to-front; fallthrough order (command, `pb_sv_`, dvar, game console command) (section 3). [O]
3. **Dvar semantics** exactly as in 4.4 (including: "dvar set" log line on every set, equal-value set clears the latch, internal source bypasses all protection, cheat test dereferences `sv_cheats` unchecked) and the retyping of user-created string dvars on registration (4.3); alphabetical (case-insensitive) iteration; 0x500 dvar limit (fatal); 12-float parse scratch ring; hash function. [O]
4. **Flag word values** must stay bit-compatible because dvar flags are exposed on the wire (`SERVERINFO`/`SYSTEMINFO` info strings, `rcon dvarlist` letters) (4.2). [O/I]
5. **Error model**: five codes, rate limit (4 errors within 100 ms => fatal), post-longjmp reset sequence (5), `\x15`-prefixed strings, `Com_Error` serialisation and the "recursive error" fatal path. A native port will replace `longjmp` with exceptions/`catch_unwind`-style unwinding but must preserve the reset order and the 0/1/2/3 distinction, plus `Cbuf_Init` on drop errors. [O]
6. **Frame loop timing**: `Sys_Milliseconds` base-from-first-call, 5 ms `usleep` in main, `minMsec`=1 busy-wait via `NET_Sleep(0)`, `Com_ModifyMsec` clamps (5000 ms dedicated) and the `Hitch warning` print at 500..500000 ms. [O]
7. **Event pump**: one console line and one UDP packet per `Sys_GetEvent` poll; ring sizes 256 with the documented overflow behaviours; packets are only dispatched while `sv_running`. [O]
8. **Memory contract** (even if the allocator is replaced): hunk sizes (`com_hunkMegs` default 160, floor 80 MiB, max 512), zeroed allocation, 32-byte default alignment, low/high marks, temp-memory magic check (`Hunk_FreeTempMemory: bad magic` fatal), `Hunk_Alloc*` failure messages (drop error), per-error `Com_PoolReset`, hunk cleared by `Com_ShutdownSubsystems`/restart. [O]
9. **Print/log behaviour** (9): stderr output, `console_mp_server.log` lazily opened after the filesystem is up, channel 4 log-only, redirect flushing for rcon. [O]
10. **Version/identity strings**: banner, `version`, `shortversion`, `arch`, `username`, `Linux Quake3 Dedicated Server` text in `--version`. [O]
11. **Startup order** in 2.2 (config/dvar/hunk/net/script/server cvar registration order matters for latched values, `+set` pre-registration and for `rcon dvarlist` output order which is alphabetical anyway). [O]
12. Observable quirks worth keeping bug-compatible only if oracle tests need them: `ttycon` forced to 0, `Cmd_ArgsFrom_08062fa8` length accounting uses `strlen(arg+1)` (off by one: first char ignored), `Dvar_ClearUnknownFlag0400` walks from pool slot 0 instead of the sorted head, `dvar_float`'s wrong error text. [O]

## 15. Naming problems found (evidence)

1. **`Snd_SetFlagByte` (0x080b1250) / `Snd_GetFlagByte` (0x080b1268)**, tag `sound/state`: they are dvar-module state. The setter stores byte 0x085b7655, the getter loads byte 0x085b7654 (objdump). 0x085b7655 is the "config-load gate" read by `Dvar_SetFromUserInput` (0x080b501c: `cmp BYTE PTR ds:0x85b7655,0`) and written only by `Cbuf_ExecuteWithLoadFlag`/`Com_ErrorRecover`; 0x085b7654 is set to 1 by `Dvar_InitSvCheats` (0x080b5138) and to 0 by `Dvar_Shutdown`, i.e. "dvar system initialised", used as the gate in `Com_UpdateQuitOnErrorFlag` (0x0809e5ca). Setter and getter therefore touch **different** bytes. Proposed: `Dvar_SetLoadingConfig(byte)` and `Dvar_IsInitialised()`. [O]
2. **`main` 0x080d4f7c** missing in `symbols.json`; exists only as `Sys_Main` (chunk_102). [O]
3. **`SV_QueryGameActive` (0x080926d6)**: its body (chunk_021) is `sv.state == 2 ? G_ConsoleCommand() : 0`; as used by `Cmd_ExecuteString` it is "give the game a chance to handle an unknown console command", not a "query". Proposed `SV_GameConsoleCommand`. [O body]
4. **Two canonical-looking `Q_stricmpn`**: 0x080b7ae2 (`Q_stricmpn_080b7ae2`, the real one, chunk_030) vs 0x080ad4dc (`Q_stricmpn`, chunk_027) vs 0x0809163e (`StrNCaseCmp`, chunk_020); the latter two are the same tolower-based routine and should share one name (e.g. `Str_NCaseCmp`) so `Q_stricmpn` is unambiguous. [O]
5. **`Com_PoolTouchAt` (0x080ac5d8)** declared `void` but returns the pool pointer (used as such in `Com_EventLoop`); name suggests no effect. Proposed `Com_PoolPtrFromOffset`. The `Com_PoolAllocInto/Into2` and `RestoreFrom/RestoreFrom2` pairs are ctor/dtor aliases of one scoped buffer; proposed `ScopedPoolBuf_Ctor/Dtor` (two aliases each). [I]
6. **`Hunk_ReallocateTempMemory` (0x080ac3a2)**: named from the error string, but the body is a header-less low-temp allocation based on `lowPermanent`; not a realloc. [O body]
7. **`Dvar_ClearFlagsIfOwned` (0x080b34da)**: acts when `OWNS_NAME` is **clear** (chunk comment itself says "does not own its name"); the name is inverted. [O]
8. **`Cmd_ArgsFrom_08062fa8` (0x08062fa8, tag `common/dvar`) vs `Cmd_ArgsFrom` (0x080602a4)**: different functions (0x1000 caller buffer + `strlen(arg+1)` accounting vs static 0x400 buffer). [O]
9. **`Com_InitStringBuffer` (0x080628b6)** is `Field_Clear` for `field_t` (0x118 bytes: `cursor`, `scroll`, `widthInChars=0x100`, buffer zeroed); chunk_007's `comStringBuffer_s` is the same layout as promoted `field_t`. [O sizes]
10. **`Com_BeginParseSession` comment** claims it "pushes anyway"; `Com_Error(0)` does not return (section 8). Chunk_029 `parse_session_s` (size asserted 0x45c4) is smaller than chunk_030 `ComParseState` (has `lastTokenPos`/`prevTokenPos` at 0x45c4/0x45c8 => at least 0x45cc). [O]
11. **`cvar_s` vs `dvar_s`**: chunks 009/020/021/024/040 call the same record `cvar_s`; chunk_009 gives `string` at +4, which is wrong (+4 is `flags`/`type`/`modified`). [O]
12. **Return type conflicts** between chunks: `Dvar_FormatResetValue/LatchedValue` (chunk_029 `uint32`/`char*` vs chunk_028 `const char *`), `Dvar_ParseEnumIndex` (029 `const char *` vs 028 `int`), `Dvar_ParseValueWord` parameter naming (028: enumCount/names; 029: min/max). The chunk_028 forms are the correct ones (numeric -0x539 sentinel, `va()` text). [O]
13. **Com_Parsestruct InfoFields** (0x080b8a36): corrupted symbol name (`Com_ParseInfoFields` expected). [O]
14. **`Sys_ReturnZero_*`, `Sys_NoOp_*`, `Tty_Stub*`, `Noop_08060b9c/08060c1a`, `Com_Noop_*`**: ~45 address-suffixed stubs; `Noop_08060c1a(int)` is invoked at four sites in `Com_Init`/`Com_Frame`/`Com_EventLoop` (looks like a removed profiler/"Com_Frame hook" call) and `Noop_08060b9c(field*)` in the tab-completion path (a removed autocomplete hook). [I]
15. **`Sys_Quit`/`Sys_Exit`**: `Sys_Quit` (0x080d3a7a) is the "final shutdown then exit(0)"; `Sys_Exit(1)` from `Sys_Error` skips all subsystem shutdown. Names are fine, but chunk_038's "Q3" comments should not be read as Q3 semantics (stderr, no `Sys_Shutdown`).
16. **Cmd_AddCommand comment**: "function is not replaced"; confirmed [O] by code, in contrast to Q3's silent replace.
