# Rust server verification, 2026-11-20

The reference is the original 1.3 Linux server with SHA-256 `05e774a3ee9fb487d4ec8a3d7d8d8e667f8ae459653e3c9e60a1c55604d5a3a7`. The [artifact inventory](server-binary-inventory.md) documents the binary and update. The pinned Rust toolchain is 1.99.1. The original ran in a private loopback-only Linux namespace. Real-data runs used German multiplayer IWDs from the read-only source or the corresponding original Windows data directory.

Build the Rust server with `cargo build --release --locked -p cod2-server`. Run all registered cases from the repository root on Linux with Bubblewrap and the original captures prepared by `gameplay.py run CASE N --server original` for N from 1 to 3.

```sh
python3 games/call-of-duty-2/tools/oracle/rust_gameplay.py \
  --reference /path/to/original/oracle/captures \
  --main /path/to/stock/main \
  --jobs 4
```

Use `--case duel_dm_toujane` for a single match. The runner records the tested executable's SHA-256, writes the case logs and `results.json` to a fresh directory under `.local/cod2-gameplay/`, and exits nonzero on a failed capture or comparison. CI can set `--output "$RUNNER_TEMP"`. The default seed matches the original's test seed. The original oracle pads later map loads to 1.15 seconds for rotation comparisons. The first three reported Rust builds ran map loads at native speed. The current launcher passes `--map-load-ms 1150` on seeded rotation cases to match the original padding. For scenarios with simulated non-LAN peers the Rust server binds all addresses inside the private namespace, allowing it to reach the synthetic authorization service there.
